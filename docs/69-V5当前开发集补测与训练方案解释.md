# V5当前开发集补测、训练方案解释与租卡建议

2026-10-13完成。用户要求补测旧V5当前指标，另询问云端GPU。无训练、无Jev请求、无租用或部署，所有已有模型和冻结数据保持原样。

## 为什么之前使用NF4与LoRA

目的是在本地RTX4060 Laptop 8GiB上以可控成本完成业务适配与可复现基座对照。NF4压缩冻结基座，LoRA只训练小量新增矩阵；语言q/v rank8沿用已有可运行配置，视觉参数冻结，因为本轮只有文本任务。梯度累积将microbatch1合成有效batch8，减少单次显存压力。完整两轮表示遍历全部训练数据两次，不是全参数微调。

2B的LoRA实际1605632参数，0.8B是1794048参数；0.8B采用BF16，并覆盖混合注意力特有的输入/门控投影。相同rank并不意味着相同可训练自由度；更多LoRA参数也不保证更好。这套固定配方是第一轮受资源约束对照，不是搜索得到的2B最优配方。不能将结果解释成2B模型能力上限。

全池均匀两轮先回答“是否只是没看完数据”，结果显示不是简单漏训；下一步若要解释2B/0.8B差距，应优先做2B适配范围或精度单变量对照。报告68的当前业务加权仍为另一项独立假设，尚未执行，不应把两类改动同时混入一轮。

## 本次为什么测两种V5

固定使用历史V5开发选择的step-7110，不按当前128条重新挑权重。未发现此前已完成这一当前协议的V5比较。旧四路由模型不是当前八动作模型，因此预先确定两种口径：

1. **当前提示迁移**：V5适配器接入与新2B相同的NF4 prepared-base加载器，使用当前八动作政策、候选及输入，动作后按需判断工具。这测试“直接换到当前协议能否用”，不是原V5接口表现，也没有对V5续训。
2. **旧接口保留**：复用serve.QwenEngine的意图/路由/工具三次前向，原政策和候选不变。旧接口拒绝未认证输入，故32条不调用；其余96条只投影旧接口支持字段，删除其无法表示的能力集合/档位/handoff_status等，不伪造认证或补造知识能力。llm只映射answer，不用金标把它拆成多种动作。

当前128条是开发集，不是新盲测或真实线上数据。32条未登录输入属于旧接口不支持，而非模型推理异常；96条中另有30条标注动作是旧接口无法输出的refuse13/retrieve12/close3/redirect2，单独列出，不隐去局限。

## 选择建议

保留旧V5作旧协议回归基线，不再用其旧402条四路由97.01%成绩代表当前八动作任务。新2B在当前协议已比V5直接迁移强，但尚未达业务门槛；0.8B现有配方更实用，但这不证明2B没有优化空间。当前服务继续Jev默认及后端权限/工具保护，本次没有做Jev新协议补测或线上替换。

## 租卡能解决什么

本地能完成当前评估与QLoRA；租卡的价值是提高吞吐、尝试更宽LoRA或BF16，减少8GiB显存带来的限制，不保证准确率。建议先按量租单张RTX4090 24GiB做25～50步探针，验证显存、实际步耗时和保存恢复后，再估预算；暂不为2B文本实验直接上多卡。全参数Adam训练2B的显存预算还包括梯度、优化器和激活，不能只按模型文件大小估算。

- [AutoDL](https://www.autodl.com/)：国内个人实验可优先考虑，其[GPU说明](https://api.autodl.com/docs/gpu/)列出硬件和资源分配方式。
- [Runpod GPU Pods](https://www.runpod.io/pricing)：训练选择GPU实例；价格随卡型、实例类别及存储而变。
- [阿里云PAI-DLC](https://help.aliyun.com/en/pai/product-overview/billing-of-dlc)：可作为团队训练任务平台。

以上于2026-10-13查阅官方页面，未创建付费实例，报价以购买页为准。费用估算应由“实测小时×实例单价＋存储等费用”得出；停机后的存储收费也应核对。当前启动脚本和进程锁使用Windows PowerShell/msvcrt，云端常见Linux环境需单独移植并验证，不能直接宣称克隆即可运行。云端包仅需处理后数据、源码和模型，不含本地密钥/私人笔记。
