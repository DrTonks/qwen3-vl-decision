## 怎样人工复查

1. 打开工作簿的“训练复核”。用表头筛选“未复核”，或者按“场景组”逐组看；可以分多次保存。
2. 先读“历史对话”，再看右侧“待补字段”“已选申请ID”，最后判断“当前问题”。同一问法在不同状态下可能应采取不同动作。
3. 核对“业务动作、意图、工具、参数JSON、标注依据”。问题不自然可以改写，但应保留可判断的业务诉求，不要只给原句加语气词凑数量。
4. 用下面的状态记录实际进度。只检查部分行，就只更新这些行；“复查说明”会自动统计。
5. 保存后运行下一节的导入命令，或直接告诉我复查已完成，我再导入、检查并安排训练。

|复核状态|何时使用|导入后的处理|
|---|---|---|
|未复核|尚未看过|保留为候选，不计为人审|
|通过|问题、上下文、标签均认可，未改内容|计入已复核数据|
|已修改|改过问题、历史、状态、标签或理由|重新校验，通过后计入已复核数据|
|待定|语义有歧义，或者动作政策尚未决定|保留记录，暂不进入训练；可以以后继续修改|
|排除|不符合业务、不自然、无价值或重复|保留审计，暂不进入训练；不需要删除行|

**不要修改样本ID、场景组、表头；不要删除、添加或复制整行。** 可以对完整表格筛选和排序，不能只排序问题列，否则会把问题和标签错配。原始 JSONL 已冻结，不直接编辑；所有修改通过工作簿进入新版本。

历史对话列是便于阅读的只读文本。若确需修改，在最右侧“历史修改JSON”填写数组，例如：

```json
[{"role":"user","content":"我想看一笔申请。"},{"role":"assistant","content":"请告诉我申请编号。"}]
```

最多4条 user/assistant 消息。修改时还要检查“待补字段”和“已选申请ID”是否一致；已选申请ID必须出现在提供的历史中。普通复核通常不必编辑此列。

## 标签速查与判断顺序

当前模型继续用四路由，不因扩充数据就假定八个业务动作已全部接通。`retrieve` 尚未接知识检索；`refuse/close` 由后端规则处理。若认为某行应为这两项，改好后标“待定”或“排除”，留作规则/协议调整讨论，不强塞进四路由训练。

判断时先看实际资金、安全争议或明确人工请求，再看必要对象/字段是否缺失，再判断是否需要查尚未提供的真实记录，最后才交回复模型解释一般问题或充分已知的信息。

|业务动作|典型问题|标签填写要点|
|---|---|---|
|tool|请查询本人申请列表|工具必须是五个现有工具之一|
|clarify|那笔申请怎么样，前文没有确定对象|工具留空，参数 `{}`|
|answer|申请编号是什么，有什么作用|工具留空，参数 `{}`；模型路由自动映射为 llm|
|human|只确认一次还款却被扣了两次|工具留空，参数 `{}`；不承诺已退款|

|工具|意图|参数JSON|
|---|---|---|
|queryLoanProducts|products|`{}`|
|queryMyApplications|applications|`{}`|
|queryMyCreditScore|credit|`{}`|
|queryApplicationDetail|application_detail|例如 `{"applicationId":62417}`，必须能从输入确定|
|explainApplicationStatus|status_code|例如 `{"status":2}`，当前只支持0/1/2|

其他意图：`ui_issue` 界面问题；`repayment` 一般还款说明；`payment_dispute` 扣款争议；`security` 身份或账户安全；`handoff` 明确人工/投诉升级；`general` 一般知识或不明确诉求。有效训练候选的意图不能留空。判断依据应是当前真实业务需求，不能参考模型预测再把标签改成预测。

建议先按场景组检查边界，再顺着组内问题和四种上下文逐条确认。特别检查“教我自己查看”与“帮我查询”、“查全部申请”与“查这笔”、“一般提前还款”与“扣款不符”。几乎同义的场景组可以指出冗余，但不要将训练组分出几条放到测试集，会造成相近表达泄漏。

## 保存、导入与继续复核

在 `qwen` 目录的 PowerShell 执行；无需启动数据库、模型或联网。

```powershell
.\.venv\Scripts\python.exe -m qwenlab.support_expansion check --source data/support-curriculum-v2

.\.venv\Scripts\python.exe -m qwenlab.support_expansion import-review `
  --project ../uestc_Integrated_Design `
  --source data/support-curriculum-v2 `
  --review .local/review/support-curriculum-v2/训练集复查.xlsx `
  --reviewer "你的名字" `
  --output data/support-curriculum-v2-reviewed-01
```

导入会检查ID完整性、标签枚举、工具参数与输入是否一致、历史状态、训练/评测隔离及源文件哈希。公式不能写入训练复核数据单元格，说明页的统计公式不受影响。遇到报错按样本ID定位：不能确定的内容先标“待定”，确认后再导入。输出目录必须是新目录，不能覆盖原版或上次导入结果。

可以继续在同一份工作簿中累计修改，仍以原版 `--source data/support-curriculum-v2` 导入，输出改为 `...-reviewed-02`。如果从上次新版的 `review.json` 制作了新复查表，才把 `--source` 改为上次新版；这种方式会保留未变条目的原审核人，待定/排除条目也仍可恢复。不要把基于原版的旧工作簿误当新版工作簿使用。

导入输出包括：所有记录、新的有效候选、仅已复核候选、逐条前后审核信息、版本哈希；不会启动训练。来源保留在版本元数据，表内不重复展示生成提示。复核、修改表示增加了人工审核，不能据此把样本写成真实线上用户记录。
