## 是否继续长训

规则在推理前冻结于 `configs/support-v6.json` 和运行协议：

1. 新业务开发集路由macro-F1至少提高0.01，或者路由正确数至少增加1条。
2. 当前业务、旧业务、两份通用开发集已有任务的accuracy和macro-F1均不能下降超过0.03。
3. 当前业务与旧业务的应转人工漏判数均不能增加。

200步评估必须同时满足这些条件才继续；1轮结束再次检查。不满足则自动停止，并保留参考适配器和各检查点，不自动降低门槛或延长训练。小开发集上的1条提升只是探索继续条件，不构成稳定泛化结论。

模型选择只用开发集。在符合回退约束的候选中按当前业务路由macro-F1选择；参考适配器也在候选中。校准集和挑战集不用于调参或选模。训练结束后仍需独立做校准、挑战验证与推理速度对比，当前runner不会把这些尚未执行的步骤写成已完成。

## 查看进度

在 `qwen` 目录执行：

```powershell
# 查看一次；只读，不启动训练
.\.venv\Scripts\python.exe -m qwenlab.support_train progress

# 每15秒刷新，Ctrl+C只退出查看
.\.venv\Scripts\python.exe -m qwenlab.support_train progress --watch
```

常见阶段：`loading` 加载模型；`evaluation` 显示对照或检查点评估的dataset/done/total；`encoding_training` 准备训练输入；`training` 更新参数；`stopped_at_gate` 因预设门槛停止；`complete` 完成训练上限；`failed` 运行失败。

训练开始后，按最近最多100步的实际训练秒数估计剩余时间。`remaining_training_minutes_to_current_target` 在200步前估到试训终点，之后估到两轮上限；**不含评估、加载、保存耗时，也不是保证会跑满两轮**。超过3分钟状态未更新会提示possibly_stale，不直接断言进程已停止。

训练前估算：首次可判断效果的结果约45–60分钟；完整两轮加评估约5–7小时。当前方案增加了通用回放、旧业务回归和中途检查，实际以日志更新为准。只看stage=training的step不能判断评估已经完成。

|位置|用途|

|`.local/support-v6-launch.json`|启动时间、启动器PID及控制台/错误日志位置；Windows虚拟环境启动器PID可能不同于status中的实际worker|

正常启动命令如下。本轮已经启动时不要重复执行；GPU与流程锁会阻止重复训练。脚本用隐藏窗口启动，环境缓存和临时文件设在项目所在D盘。

```powershell
& .\scripts\start-support-v6.ps1
```

若意外中断，确认原进程已退出、查明错误后可恢复：

```powershell

```

恢复会核对协议及检查点哈希，恢复LoRA、优化器和随机状态；最多重做最近一个检查点后未保存的步骤。断点处的开发门槛不能被恢复操作绕过。已完成或因效果门槛停止时，恢复不会授权修改门槛。协议或数据变更需要新实验版本，不能直接覆盖冻结文件。
