# 金融客服训练集筛选与少数动作补充

日期：2026-10-01。本轮交付训练用途的金融客服八动作文本版本；没有启动训练、模型API、部署、Git提交或推送。范围是本项目贷款服务平台，不宣称覆盖银行、保险、证券等全部金融业务。

## 为什么先筛选，再补数据

旧公开改写队列按用户要求停在23,173条、50.04%。这个百分比是来源改写验收进度，不是模型训练进度，也不是训练发布质量得分。旧队列保持暂停，本轮独立准备新版本。

数量不是唯一问题：旧候选偏向文档与产品问题，引导、拒绝和结束较少；产品审批参考分与个人评分的量纲存在混用疑似；旧作业的批次通过也不代表每条都被独立逐条读过。因此，本版先依据真实复核覆盖筛选，再补薄弱动作，不继续堆满旧队列。

## 来源筛选账本

|环节|条数|处理含义|
|---|---:|---|
|旧已验收候选|23,173|旧文件及其哈希保持原样|
|评分尺度词面疑似|1,473|不是1,473条已确认错误|
|按受影响378个来源组保守隔离|2,945|连同可能继承错误事实的历史一起隔离|
|另外缺少逐条独立实读记录|8,331|批次抽查通过仍不满足本版逐条实读要求|
|可进入本轮筛选的旧候选|11,897|源、旧审核绑定有效，且有对应实读ID|
|本轮新增候选|2,497|全部保留AI合成来源，须全量独立复核|

独立审查实际读了81条旧疑似样本：其中80条不同CrossWOZ来源组样本有79条明显量纲混用、1条词面误报；另1条MASSIVE样本有相同问题。这支持先保守隔离，不能外推成全部疑似都错误。该误报和同组其他正常句也暂时被隔离，账本明确记录这项代价；本轮没有全局替换数字或覆盖旧验收文件。

本项目产品`AcceptScore`是0–100量纲的审批参考值，seed为20–65；个人`honesty_score`是另一字段。二者不能混作同一评分，模型也不能将参考值当作真实审批通过率。

## 新增内容与独立审查

|稿件|条数|主要目的|
|---|---:|---|
|scope|967|588引导、250结束、82澄清，另47条业务/风险边界对照|
|safety|1,330|800拒绝、350人工、100结束，另80条正常回答/文档检索对照|
|core|200|80澄清、55工具、45回答、10检索、10人工；100组可见状态对照|

三名子agent分工起草与交叉审查，新增稿全部独立逐条读取，绑定最终文件SHA256及实际读取ID。安全稿发现的四处请求歧义已修订回读；范围稿将“应提供哪些信息给你”与实际故障追问分开，并为少量一般预算例补充可见贷款语境。它们仍是**AI合成、独立agent复核的数据，不是新版本人工复核或真实用户记录**。

关键边界如下：

- 合法域外请求使用`redirect`；涉及旅游、医疗等词汇的贷款用途仍在服务范围，不能见到关键词就引导走。
- `refuse`针对明确造假、越权或不允许操作；正常退款、更正记录、提供合法材料不能一概拒绝。
- `human`用于明确人工诉求、具体争议或现有工具无法处理的个人事项；人工未接通时，不声称工单已经建立。
- `close`只结束当前咨询；感谢、撤销贷款申请、关闭账号、未解决的风险分别处理。
- `clarify`指出真实缺失字段；“怎么提供报错信息”一般可直接回答，不必再问同一个问题。
- `tool`只选择当前五个只读工具，个人身份、完整申请编号及状态参数必须落地。当前后端全部工具要求登录，产品目录工具也遵守这个契约。
- `retrieve`依赖能力快照中的正式文档集合。知识库尚未建成；`planned-kb-v1`是规划能力模拟，`current-no-kb-v1`是无知识库对照，不能凭训练标签声称服务已具备检索能力。
- `answer`解释已给文字或已知信息；无工具、无正式规则时只能如实说明限制，不能填造原因。

## 最终选择

最终数量、认证交叉分布、来源家族数以`data/financial-training-text-v1/manifest.json`为准。建议目标是采样预算，不通过复制或错标强行凑齐。

|动作|建议目标|实际训练条数|
|---|---:|---:|
|澄清 clarify|1,600|1,239|
|检索 retrieve|2,500|2,500|
|工具 tool|2,200|1,894|
|回答 answer|2,000|2,000|
|人工 human|1,500|1,366|
|引导 redirect|550|550|
|拒绝 refuse|900|900|
|结束 close|600|600|
|合计|11,850|11,049|

本版不要求八类完全等量。最多类与最少类约4.55倍，工具、澄清、人工尚未达到建议目标，但满足预先设置的发布覆盖底线。后续应根据独立开发集的错误类型和场景覆盖补充，不能仅为数字齐平复制语句。

筛选对完整可见输入去重；相同输入却有不同工具、参数、文档集合或缺失字段会报冲突。数字/产品名掩码只做词面结构筛查，不等于完整语义去重。来源家族与跨状态同话语对照在选择前联合分组，被剔除的重复来源仍能连接保留兄弟样本。每个动作在同一家族最多20条，避免多数动作挤掉必要的不同动作对照。

来源家族数不能当作独立业务情境或真实用户数。例如新增800条拒绝主要来自40个主题家族，每家族20种表述，另有正常请求对照；并非800种独立风险。后续评测必须按来源、改写族和业务语义再次检查隔离，不能随机按行拆分。

实际选中8,710条旧稿、2,339条新增稿；另外3,345条通过来源门槛的候选因采样预算未选。本批完整输入与数字/产品词面模式筛查没有发现可删除的重复，不能把这3,345条称为重复或错误。总计5,669个来源关联组、4,361条带短历史；组数是归源指标，不等于5,669种独立金融业务。12个分片每片最多1,000条，最大约2.46MB，整个发布包约36.31MB。

八动作覆盖不代表每个子能力均已充分覆盖。当前工具样本分布：产品目录920、单笔申请458、申请列表316、个人评分184、状态解释16；规划知识能力11,039条，当前无知识库能力仅10条。这两项是下一版需优先补充的薄弱点，并在独立评测中专门分层；本轮不临时更改冻结发布或据此宣称可立即替换业务模型。

## 文件与复查入口

|位置|用途|
|---|---|
|`data/financial-training-text-v1/parts/part-*.jsonl`|正式训练分片，包含input、标注、来源和复核信息|
|同目录`manifest.json`|数量、动作编码、文件哈希、来源绑定|
|同目录`selection-ledger.jsonl`|隔离、去重与未选原因|
|同目录`groups.json`|全部本轮候选的来源关联及是否选中|
|同目录`review-evidence.jsonl`、`reviews/`|选中ID、实际独立读取ID、原复核包、内容哈希|
|同目录`NOTICE.md`、`licenses/`|MASSIVE/CrossWOZ归属、修改说明及许可|
|`.local/financial-training-release-v1/additions/`|三份新增候选与修订记录，Git忽略|
|`.local/financial-training-release-v1/human-review/by-action/`|按动作可读Markdown，仅为辅助阅读|
|`.local/financial-training-release-v1/human-review/cases.jsonl`|可编辑工作副本，明确标成未批准训练候选|

从拒绝/引导、结束/回答、追问/工具、争议/人工这四类边界开始读。每条都同时看当前问题、最多四条历史、认证状态、可用工具/文档集合和理由；不要只凭问句猜标签。

若需要修改，编辑工作副本`cases.jsonl`中的`input`或`annotation`。`annotation`的action、tool_name、tool_arguments、retrieval_collection、missing_slots必须一致；修改理由也保留。不要编辑正式分片、manifest、审核证明、ID、provenance或把人审字段直接改成true。运行`check-review-copy`检查语法、业务契约和差异；结果记入`human-review/changes.json`，**通过结构检查仍需独立复核后制作新版本，不会覆盖当前发布，也不会自动批准训练**。修改Markdown不会改变实际数据。

## 可复现命令

均在仓库根目录运行；依赖使用现有环境，不下载模型或调用API。

```powershell
. .\scripts\use-env.ps1

# 公开版本的包内完整性、标签契约、分片与审阅证据自一致性
.\.venv\Scripts\python.exe -m qwenlab.financial_release validate

# 本机完整来源存在时：还会验证原源/审核哈希并重建选择，逐行核对输入和目标
.\.venv\Scripts\python.exe -m qwenlab.financial_release validate --verify-local

# 导出仅含可见输入和紧凑目标的训练适配文件；不会训练
.\.venv\Scripts\python.exe -m qwenlab.financial_release export-training

# 创建可读材料与可编辑副本；已有副本时拒绝覆盖
.\.venv\Scripts\python.exe -m qwenlab.financial_release review-copy
.\.venv\Scripts\python.exe -m qwenlab.financial_release check-review-copy

# 发布代码单测
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_financial_release.py -v
```

本轮已生成复查副本，直接打开即可；不要重复运行`review-copy`覆盖自己修改。训练适配输出在`.local/financial-training-release-v1/train-input-target.jsonl`。只有`input`字符串进入模型编码；动作、工具和参数是监督目标，来源、理由与复核状态都不放进输入。A–H依次对应澄清、检索、工具、回答、人工、引导、拒绝、结束；这是新动作契约，不能直接套用旧V5工具合并八类的checkpoint头。

实际验证：12项新发布单测、全部68项financial单测通过；真实构建及`validate --verify-local`成功，适配文件与复查副本共11,049行，副本初始差异为0。发布包路径与类密钥模式扫描未发现本机绝对路径或类密钥字符串；本地工作副本、适配文件及失败staging均被Git忽略。原队列、原源和冻结评测哈希由来源保护检查确认未变。

原源齐备且各稿已独立复核的构建者可用`prepare`准备基线、`build`建立新发布。`build`拒绝覆盖已存在版本；克隆GitHub得到的公开分片无需`.local`即可`validate`和`export-training`，但不能凭公开分片重建被Git忽略的原源与实际审阅过程。

便携验证证明相对manifest的字节完整性和包内自一致性，**不是数字签名，也不能认证整个manifest与全部证明是否被共同改写**。`--verify-local`额外对仍保持原样的原源和独立审核记录进行逐字段重建核验。分片固定LF；Git对该数据目录关闭换行转换，原审核包字节保持不变。

## 下一步训练条件

目前只完成训练部分，`independent_evaluation_ready=false`。尚未生成新八动作的独立开发、校准、最终测试集，也未有这份新数据上的模型成绩。已见过多次的旧挑战成绩不能充当本版盲测，不用旧测试错题继续造训练数据。

下一阶段先定义独立场景族和保留来源，制作冻结的三套评测；纳入合法/非法对照、未认证查询、短历史、人工未接通、知识不可用，以及工具参数落地与人工漏判。新评测要重新进行完整八动作标注；旧四路由成绩只做另列回归。

随后冻结数据哈希、动作提示、模型候选与训练预算，先用原始模型跑基线，再做一次短试训验证是否真实改善。只有开发门槛通过才延长训练；校准集调温度/回退阈值；最后测试用于一次固定候选结论。八动作分类与具体工具/参数能力要分别验证，不能用动作准确率代替完整工具执行正确率。图文数据和更小模型仍是后续独立工作，本版没有图像样本、下载或小模型性能结论。
