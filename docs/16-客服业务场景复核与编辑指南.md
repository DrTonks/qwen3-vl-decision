## 这份数据能用来做什么

`data/support-design-v1/` 有 400 条 AI 起草的表达、90 个场景组，全部待人工复核。它依据项目产品、申请、材料、合同、认证等代码设计，适合讨论客服下一步行为；不是已批准的八分类金标，也不是能够直接请求当前服务的验收脚本。`check` 校验通过只能说明稿件结构与生成器一致，不能证明标签正确或业务能力已接通。

生成时的源码快照已有变化：`后端/api/agent.js`、`后端/server.js`、`Uni-ui/pages/profile/support.vue`。旧文档与数据中的 `current_support`、`taxonomy_status` 是当时的描述。现在已有持久会话、动作校验、只读工具和 Jev/Qwen 适配，但尚未实现完整八动作流程。不要据旧文字判断当前实现，也不要自动重新生成覆盖原稿。

## 八个业务动作和当前实现的区别

|候选业务动作|当前情况|如何验收|
|---|---|---|
|tool|已开放产品、本人申请列表、本人详情、信用分、状态解释五个只读工具|分别检查选工具、参数、身份归属和返回数据。|
|clarify|已有缺申请编号、无效状态和歧义追问|多轮补槽仍需覆盖真实口语和标点。|
|answer|已有模板，回复模型可选；模型目前只处理一般帮助|模拟 facts/UI/knowledge 不会自动变成运行时可信事实。|
|human|能表达需要人工，但没有真实工单/转接|只能验收如实告知，不能要求“已接通人工”。|
|refuse|已有受限操作的规则拦截|须检查否定句、合法申诉和上下文，关键词命中并不等于正确。|
|close|已有明确结束处理|验证结束咨询不改变贷款，新问题能够继续。|
|retrieve|未接知识库，也未列入运行时动作协议|作为后续能力需求，不计入当前可执行覆盖率。|
|redirect|未作为独立运行时动作|先确认产品规范，再加入协议与评测。|

当前 Qwen/Jev 分类器输出的是 `intent / route / tool`；route 只有 `tool / clarify / llm / human`。后端再映射为动作，并对部分拒绝/结束情形做规则处理。`configs/decision-v5.json` 中另一项名为 `action` 的八候选题是“三种非工具路由 + 五个工具”，**不是本稿的八种业务动作**，常驻服务也没有调用那项题目。不能把这两套“八类”当成同一个测试任务。

## 如何编辑

在 qwen 根目录执行以下命令，创建自己的工作副本。`-NoClobber` 防止覆盖已做的复核：

```powershell
New-Item -ItemType Directory -Force .local/review/support-v1 | Out-Null
Copy-Item data/support-design-v1/review-template.jsonl .local/review/support-v1/review.jsonl -NoClobber
Copy-Item data/support-design-v1/draft-cases.jsonl .local/review/support-v1/cases.jsonl -NoClobber
```

1. **只调整期望动作或解释**：修改 `review.jsonl` 中相同 id 的记录。填写 `status`、`final_action`、`final_tool`、`final_arguments`、`final_next_step` 和 `notes`。动作规范尚未批准时，保持 `taxonomy_approved: false`。
2. **调整问题、历史、模拟状态**：编辑 `cases.jsonl` 中对应案例的 `inputs`，并在复核记录说明修改原因。使用 UTF-8，保持每行完整 JSON；对象内引号需按 JSON 规则转义。
3. **新增场景**：在案例副本中复制完整结构，换一个唯一 id 和新的 `scenario_group`，同时新增对应复核记录。语义相同的改写仍属于同一组。
4. **删除或存在争议**：分别记为 `excluded` 或 `needs_discussion` 并解释原因；不要直接删掉记录导致无法追溯。

例如，确认 C01-1 后的记录可以写成以下内容（为方便阅读展开；保存到 JSONL 时放在一行）。这只是填写示例，不代表已经替团队批准：

```json
{
  "id": "C01-1",
  "status": "accepted",
  "reviewer": "reviewer_01",
  "final_action": "tool",
  "final_tool": "queryLoanProducts",
  "final_arguments": {},
  "final_next_step": "查询当前已上架产品，展示真实返回的产品信息；最高额度不代表本人获批额度。",
  "notes": "按产品查询能力复核；利率、期限不在此工具返回字段中。",
  "taxonomy_approved": false
}
```

状态建议值：`pending / accepted / revised / needs_discussion / excluded`。非工具动作的 `final_tool` 用 `null`、`final_arguments` 用 `{}`。不确定时保留争议，不要为了统计准确率强行给唯一答案。

`.local/` 已被忽略，适合成员各自工作，但不会自动随 Git 分享。团队达成共识后，应去除姓名和真实个人数据，另建公开的 reviewed v2；当前尚无自动合并、转训练标签或在线执行转换器。不要直接拿 `proposal` 当最终答案训练。

## 优先调整的业务边界

- **普通操作诉求与非法操作分开**：M16 的“帮我还一下”需要结合历史。可以解释还款步骤，不可直接扣款；是否记为 answer/retrieve/refuse 由团队明确。
- **缺工具不自动等于转人工**：B15/B16/B17/B26 涉及利率、合同、材料等缺口，应注明是补工具、补文档、引导页面还是确需人工。已实现的业务 API 不等于客服已授权的工具。
- **模型输入不能靠假设补齐**：B01/B02/B05 和 M05 等含完整或过期事实、失败次数；B06/M14 含按钮页面状态。这些字段当前不会被模型适配器完整传入，不能删掉状态后仍要求原答案。
- **编号和状态需要上下文**：C03、M02、M03、M12 要覆盖“76001 这笔”“76001。”“不对，是 76002”和先前消息里的状态码，核对模型选择与后端参数解析两层。
- **不能为迁就解析器修改合理问题**：C03-2/3/4/6、C05-2/4 即使预设正确工具，当前参数解析仍会追问；M03-1 的“76001。”即使有 pending 也未识别。这是待修复回归用例，不应一律把期望标签改成 clarify。
- **详情字段不足以解释原因**：B22-1 希望从详情取得审批摘要，但当前工具没有返回拒绝原因/审批摘要，状态“未通过”不等于具体原因。应补经过审核、允许向用户展示的解释字段，或明确能力不足时的处理；不能编造原因。
- **前置身份校验单独统计**：12 条登录/角色场景属于网关验收，不能混进模型动作准确率。
- **测试夹具与真实数据分开**：76001/76002、612 分等是构造数据，不保证数据库存在。在线验收要使用独立验收库里的真实测试 ID 和所属账号，不能只替换文本却遗漏 arguments/history/state。
- **已有材料不能替代正式条款**：提前还款、费率、准入解释等应有业务确认、有效版本和适用产品，不把代码示例当承诺。

## 如何验证和冻结

原始稿件结构检查（不会检查人审副本，也不会判定业务正确）：

```powershell
.\.venv\Scripts\python.exe -m qwenlab.support_design check
```

副本的基础语法和唯一 ID 检查：

```powershell
.\.venv\Scripts\python.exe -c "import json,pathlib; p=pathlib.Path('.local/review/support-v1'); sets=[]; [sets.append([json.loads(s) for s in (p/name).read_text(encoding='utf-8-sig').splitlines() if s.strip()]) for name in ('cases.jsonl','review.jsonl')]; assert all(len(rows)==len({r['id'] for r in rows}) for rows in sets), 'duplicate id'; assert {r['id'] for r in sets[0]}=={r['id'] for r in sets[1]}, 'case/review id mismatch'; print('JSON syntax and ID pairing OK; business labels still require review')"
```

同组变体必须留在同一个 split。先确定业务规范和可用输入，再按组去重、划分训练/验证/验收，并冻结版本。报告分别统计模型原始路由、后端最终动作、工具参数和执行结果；将未实现能力、输入适配问题与模型误判分开列出。

`build --rebuild-unreviewed` 会检查生成稿哈希，只适合未开始复核的重建，**不用于保存人工修改**。现有 `check` 还要求总数 400、全部 pending、与生成器一致，因此人工编辑副本后不应期待它验证人审标签。
