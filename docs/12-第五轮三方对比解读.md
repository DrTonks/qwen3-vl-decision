# 第五轮：原始 Qwen、微调 Qwen 与 Jev 的效果和速度

2026-09-27 完成。原始模型为 Qwen3-VL-2B-Instruct NF4，微调模型为开发集选中的 step-7110，Jev 成功响应均核对为 jev-1.13.0。先冻结协议和测时样本，再执行比较；没有按本次测试结果重选模型或继续训练。

## 客服效果：同一政策、同一批 402 条输入

|指标|原始 Qwen|第五轮 Qwen|Jev|
|---|---:|---:|---:|
|意图准确率|76.12%|99.75%|99.25%|
|业务路由准确率|36.32%|97.01%|87.06%|
|确实需要工具时，路由和工具都选对|82/116（70.69%）|111/116（95.69%）|114/116（98.28%）|
|必须人工却未转人工，越少越好|98/110|0/110|31/110|
|无需人工却转人工，越少越好|—|12/292|0/292|
|三个字段同时正确|85/402（21.14%）|389/402（96.77%）|349/402（86.82%）|
|请求失败|0|0|2|

路由是 tool / clarify / llm / human 四类；本表不代表截图所列新八类动作已经训练完成。工具联合正确要求先选 tool，再选对具体工具，避免大量 none 抬高成绩。

Jev 新增 402 次评估，一次超时、一次 HTTP 520，均按错误计入主表，没有重试；两条真实标签都是 tool。只看成功请求，Jev 意图为 399/400=99.75%，与 Qwen 在相同 400 条上的准确率相同。因此，不能将主表 0.50 个百分点的意图差距解释成模型能力优势。Jev 在 114 条成功的工具必要请求上全部选对。

Qwen 路由提升集中体现为更贴合本项目政策。它的 12 条路由错误都是过度转人工：5 条应调用工具，7 条应追问。Jev 的 31 条人工漏转分别去了 tool 22 条、clarify 5 条、llm 4 条。后续应复核这些边界标签，而不是把所有分歧都称作通用理解能力差距。

排除 API 失败，按 21 个表达组做配对 bootstrap：Qwen−Jev 的路由差为 +9.50 个百分点，95% 区间约 [+5.08,+13.04]；意图差为 0，区间约 [-0.76,+0.74]。区间只反映当前合成表达组的抽样变化，不能涵盖共享生成器和未经人工复核造成的系统偏差。

## 速度：同 32 条输入，当前机器实测

|调用方式|P50|P95|
|---|---:|---:|
|原始 Qwen，完整输出层|560.10 ms|607.82 ms|
|第五轮 Qwen，完整输出层|576.45 ms|627.44 ms|
|第五轮 Qwen，候选行裁剪|565.93 ms|616.45 ms|
|Jev API|489.01 ms|596.86 ms|

P50 是中位耗时，P95 反映较慢请求。当前本地硬件是 RTX 4060 Laptop 8GB；batch=1。本地每个请求依次执行意图、路由、工具三次前向；Jev 一次 HTTP 返回三项。本地包含分词和结果回到 CPU，不包含加载、预热；API 包含网络。这是实际调用方案比较，不是同硬件的纯模型算力比较，也没有测并发吞吐。

本地三种方式交替顺序、每条重复三轮，共 288 次；Jev 使用 402 条评估中相同 32 个 ID 的一次计时，32 条全部成功。两次 API 失败不在该速度子集中，不能据 P95 宣称没有失败或超时风险。原始 Qwen 在同一 PEFT 模型实例禁用 LoRA；逐条选择与独立基础模型已有预测完全相同。候选裁剪也没有决策差异或回退。

- LoRA 完整输出比原始 Qwen 的 P50 增加约 16.35 ms（2.92%）。这是额外投影运算的开销，不能称为模型“思考更久”。
- 裁剪从 576.45 降到 565.93 ms，节省约 10.52 ms（1.83%）；优化后仅比原始 Qwen 慢约 5.82 ms（1.04%）。
- 当前 Jev 中位耗时更低；裁剪 Qwen 比 Jev 多约 76.91 ms（15.73%）。之前第四轮不同提示/样本的 382 对 573 ms 不能混入本表。本次也不能分离网络状态、服务负载与输入变化各自的影响。

## 结论与下一步

补充复测：[历史383ms复现报告](../results/joint-v5/latency-reproduction/report.md)。原第四轮32条条件重跑三轮P50为398/413/385ms，合并406ms；第五轮模型跑同一批旧提示为397/369/382ms，合并375ms。可以观察到约380ms，但存在会话内波动，不能承诺稳定383ms。新版三次前向累计平均输入从1551增加到2226token（约43.56%）；不能把旧提示的速度与新政策的准确率拼成同一结果。

微调对当前政策的客服路由、公共中文分类有明显效果；本次速度尚未超过 Jev，工具必要子集也略低。业务集来自与训练共享生成器的 21 个留出表达组，没有独立人工验收，因此只能说当前基准上的适配有效，不能宣布真实客服全面胜出。

优先收集和复核独立人工数据，检查 Qwen 的过度转人工、Jev 的人工边界分歧，再做新八类动作专项实验。减少串行前向有更大的速度潜力，但现有未专项训练的动作合并实验漏转人工，不能只因快就采用。单纯继续增加训练时长不会解决三次前向的架构开销。
