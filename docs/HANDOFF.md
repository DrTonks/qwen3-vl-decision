## 接手顺序与验收

1. **近期先推进 0.8B 业务加权。** 按报告 70 的独立准备版本，将当前业务权重固定为其他层的 3 倍，模型、数据、学习率和步数保持不变。下一步是独立执行器接入及真实 GPU 探针，不是直接启动旧完整训练命令。2B 的 LoRA 覆盖或精度对照另行安排，不混入本轮。
2. **准备执行器并做短探针。** 核对来源、标签空间、可训练参数和输入预算；完成 CPU 回归与短 GPU 运行，实测显存、步耗时以及跨进程保存恢复。需要云端时先完成下节的环境移植，按探针结果估预算。
3. **完成受控训练与开发验收。** 沿用预先冻结的门槛，同时看动作、工具联合、人工漏判、误拒绝及不可用能力选择，保存逐条预测与选择记录。可参考 [2B 执行配置](../configs/financial-2b-full-coverage-execution-v1.json)与[完整协议](66-2B完整覆盖训练与分批发布.md)。不因整体准确率高而放宽单项门槛。
4. **只有合格候选进入后续选型。** 独立校准后一次性评最终集；同机器、同输入、同计时范围比较速度。[报告72](72-Jev代理补测与请求恢复.md)已完成当前128条开发集Jev对照（85.16%），尚未做独立校准或最终测试。Jev 缓存仅在输入、候选和政策一致时复用；新增 API 请求先确定预算，不能默认旧分数等于新协议结果。
5. **验证真实客服链路。** 单独验证登录状态、工具白名单、参数校验、工具失败和转人工状态。分别报告模型原始决定、后端拦截和端到端处理结果；后端拦截成功不能记作模型答对。

每个新实验交付：冻结配置与哈希、数据来源、实际启动命令、环境版本、训练日志、逐条开发预测、门槛判断、耗时与显存、结论及限制。只有实际完成的校准、盲测或接入才能出现在“已完成”中。

## 环境与复现

查看报告和公开证据无需 GPU。运行训练需 Python 3.12、兼容 CUDA 的 NVIDIA 环境及下载好的模型；当前已验证路径是 Windows PowerShell。本地参考硬件为 RTX 4060 Laptop 8GiB。

以下为仓库已有的环境安装入口，**从仓库根目录执行**，会下载依赖；不是训练启动命令：

```powershell
# 基础环境与训练依赖；需要已安装 Python 3.12
.\scripts\setup.ps1
# 当前 Qwen3.5 及新 2B 实验使用的叠加环境
.\scripts\setup-qwen35.ps1
# 服务依赖仅在需要运行 Flask 服务时安装
.\.venv-qwen35\Scripts\python.exe -m pip install -r requirements-serve.txt
```

`setup-qwen35.ps1` 的 `.venv-qwen35` 通过本地 `.pth` 复用 `.venv` 的部分依赖，两者不可单独搬走。`pyproject.toml` 未声明全部运行依赖，单独 `pip install -e .` 不够。环境与缓存脚本使用仓库相对路径；仓库置于数据盘即可让对应缓存位于数据盘。不要提交生成的环境、缓存或本地路径配置。

历史实验执行方法分别见 [0.8B 协议](64-完整覆盖两轮训练协议与启动记录.md)、[2B 协议](66-2B完整覆盖训练与分批发布.md)与 [V5 补测](69-V5当前开发集补测与训练方案解释.md)。这些命令可能依赖未上传的模型、检查点和日志；新克隆不能保证直接重算所有历史运行。完整产物齐备的原实验工作区可运行：

```powershell
# 离线重算已有结果，不启动训练或 API
.\.venv-qwen35\Scripts\python.exe scripts/audit-financial-2b-full-coverage.py
.\.venv-qwen35\Scripts\python.exe scripts/audit-financial-v5-current.py
```

云端常见 Linux 环境尚需移植 PowerShell 启动脚本及 Windows `msvcrt` 进程锁，并验证依赖、保存恢复和退出行为。更大显存可用于尝试精度或适配范围，不代表准确率必然提高。先做短探针，再安排完整预算。

## 知识检索与多模态如何跟进

- **知识检索**：业务方整理有版本的产品、审批与还款规则；检索模块负责召回、来源和有效期，决策模块负责选择 retrieve。验收要含无答案、过期规则、冲突规则和服务不可用回退，不能让模型编造平台政策。
- **截图理解**：建立按钮禁用、申请状态、报错提示等图文与可信后台状态配对样本；图片相似模板和同一业务故事按组隔离。先做独立多模态基线，再决定是否训练视觉侧。
- **回复与执行**：本仓库只解决决策组件；自然语言回复、数据库工具、鉴权、人工受理仍由对应模块负责，需在业务项目单独验收。
