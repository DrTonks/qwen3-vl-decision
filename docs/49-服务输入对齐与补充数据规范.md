# 服务输入对齐与补充数据规范

2026-10-03，承接文档48。**本轮完成后端参数解析修复、实际输入导出与补充数据规范；没有训练新模型，也没有新的模型准确率。** 两个已有检查点仍未通过原门槛，不能部署为合格候选。政策、原训练/开发/校准/最终数据及实验结果均保持冻结。

## 1. 已完成的工程修复

相邻业务仓库后端的 `services/customerSupport/parameters.js` 同时被规则、旧模型适配器、新金融模型适配器及执行边界使用。状态解析现支持明确字段表述，例如“页面状态字段显示为0”，以及字段说明中的“显示、出现、标注、记录、标记”。没有采用“找到状态附近的任何数字”规则。

以下行为已回归：

- 0/1/2分别保留；同一个状态明确重复出现不会因重复计数而追问。
- 多个不同状态、未知状态、正负号、小数、科学计数、金额、日期、区间及无关联数字不执行状态工具。显式状态中存在无效数值时，不忽略它而擅自选另一个有效数值。
- “产品代码2”不会再被通用“代码”后缀误识别为申请状态。
- 编号只来自当前明确引用、可信会话的“这笔/那笔”指代或等待编号时的纯数字回复。金额、日期、多编号、超范围编号不能落入工具参数；没有改写原编号解析实现。
- `modelInput`、`toDecision`、`groundDecision`复用同一套参数来源。历史里出现过的状态不自动成为当前工具参数，客户端不能伪造认证、可用工具和结构化state。
- 澄清状态→用户补充数字→工具解释→清除待补字段已经通过内存仓库流程验证。

输入适配器版本为 `financial-node-input-v1.1`，在provider审计、编排审计和健康信息中可见。动作政策仍是 `support-financial-v2`，政策SHA保持 `98f11b5acadf1f549d63677cd3010c76445c9c749c0f1d23e9ca05d67d1e5d91`。输入适配器版本和政策版本分别记录；修改正则不等于修改动作标签政策。

正则只识别列明的明确语法，不声称覆盖任意自然语言、否定、纠错或复杂句。不能可靠确定参数时继续追问；模型负责选择动作/工具，不负责创造编号。数据库的账户归属检查仍由工具独立执行。

## 2. 用真实Node构造训练候选输入

新增 `后端/scripts/export-financial-input.cjs`。它直接调用生产 `chatInput` 和 `financialContract.modelInput`，不复制另一套Python预处理。输入是**离线合成的服务端上下文夹具**，不是客户端可提交的权限声明，也不是生产API。

在业务仓库的 `后端/` 目录运行：

```powershell
New-Item -ItemType Directory -Force tmp | Out-Null
node scripts/export-financial-input.cjs tests/fixtures/financial-input-example.jsonl tmp/financial-input-example.jsonl
```

输出已存在会拒绝覆盖；重复运行应改用新文件名。导出本身只需要Node，测试需先用 `npm ci` 安装项目依赖；无需启动模型、MySQL或业务服务器，不读取密钥。

每行输入字段：

|字段|来源/限制|
|---|---|
|`id`|唯一的合成样本标识，只允许字母数字、下划线和短横线|
|`context.message`|当前咨询字符串；按真实入口trim，1–2000字符|
|`context.authenticated`|离线模拟服务端认证状态，必须显式boolean；不是客户端权限|
|`context.state`|只允许`pending`和`selectedApplicationId`；不可手写`application_id`/`status_code`|
|`context.history`|仅user/assistant内容；真实适配器保留最后4条，每条最多800字符并脱敏|
|`context.availableTools`|可省略为当前5个只读工具；显式空列表表示均不可用；未知工具拒绝|

输出包括原样本ID、实际`input`、输入SHA、适配器版本、政策SHA以及6个依赖源文件的相对路径和SHA。输出不携带原始身份、不包含本机绝对路径。自动脱敏仅覆盖已实现的常见证件/手机/银行卡/邮箱模式，不能替代真实日志的隐私审核；本工具当前只用于合成数据。

输出强制 `training_eligible=false`，不自动生成标签或进入训练。已登录标为`current-service-projection`，未登录标为`preauth-component-only`——实际聊天入口仍要求已登录。工具不伪造未来知识库或人工连接器；未来能力输入必须作为独立组件场景编写并验证。

6条示例的实际导出见 [工程输入证据](evidence/financial-input-current-v1.jsonl)。这些示例及代码回归样例仅用于工程验收，**不加入训练或模型盲测**。

配额是覆盖目标，不是为了凑数强改标签，也不是线上类别先验。当前服务无知识库，不能为了八类均衡制造retrieve正例；未认证不得有tool正例。人工连接器不可用不改变合法转人工意图，但实际回复必须说明未建单/未转接。

当前服务1,200条中，建议900条由上述真实Node投影生成，300条作为宽契约的组件鲁棒性输入。后者允许正文有可确定参数但不额外提供结构化字段，单独记录构造方式；不能通过伪造可信服务state来宣称它是当前后端输出。两种输入分别报告、按故事组绑定，不能跨训练/评估拆开。字段存在不是标签，字段缺失也不自动等于clarify。

参数类覆盖：当前服务360个tool目标建议为产品70、本人列表70、申请详情100、信用分60、状态解释60。详情/状态以及对应clarify，覆盖正文明确值、可信会话指代或待补回复、缺失值、多个候选、无关金额/日期干扰；没有唯一合法参数时标clarify。语义足够清楚但超出现有工具字段的问题，不能因为问到了申请就标详情查询。

所有动作都应覆盖简短表达、正式表达、口语、少量错别字、上下文接续。重点区分：询问“能否办理”、实际要求办理、请求当前只读数据、正式知识问题、合法但当前工具不能办理、越权/篡改/绕过请求、单纯超出贷款范围，以及致谢和明确结束。拒绝针对不允许的请求，引导针对无关服务领域，不能把所有非金融公开语料都标refuse。

## 5. 如何审核与避免再次训练偏置

每条记录保留 `id/source_id/source_group/origin/licence_or_permission/cohort/input_layer/context_or_input/expected_action/expected_tool/label_reason/review_status/training_eligible`。合成仍标 `ai_synthetic`，经人复查可额外记审核者/时间，不把来源改成真实用户或“非AI”。公开数据改写保留来源、许可和父子关系；歧义标quarantine，不强行猜标。

建议先做160条小批量，由独立审核者检查动作/工具/参数及能力，再完成剩余候选。最终逐条独立标签复核、按关联来源整组隔离、结构校验、语义近重复检查、全部输入的token无截断检查通过后才能冻结。训练作者不读评估原文；独立的重叠检查只回传需隔离的训练ID，不回传开发/最终题面用于改写。

单纯追加：当前服务从574/11,756=4.88%，变为(574+1,200)/(11,756+1,600)=**13.28%**，仍不足以把训练重心转到实际服务。因此后续实验需要明确分层采样；可讨论的起始配比为当前服务60%、未来检索25%、登录前15%，先记录各组有效曝光次数，不能靠重复少数模板虚增独立样本量。此配比是**下轮待冻结设计建议**，没有修改本轮执行器/门槛。

最小对照应保持官方0.8B起点、优化器/步数预算一致，比较“仅对齐输入”与“对齐输入＋独立补充＋分层采样”，必要时再拆开采样因素；否则无法判断改善来自哪一项。保留原开发评估用于持续回归；它已被诊断，不再宣称是新盲测。校准只调温度/阈值，最终集在选型与校准冻结后才评，不拿最终错题训练。新服务流程测试单独记原始动作、后端保护后动作、工具与参数和响应，不与组件成绩混算。

完成本规范的下一步是**生成首批160条独立候选并复核**，再补齐至1,600条并冻结新数据/新实验协议。模型训练尚未启动，不承诺“再训练多少分钟就一定达到Jev”。后续决定训练预算时沿用长训实测与小批探针共同估算，而非只看短探针中位数。
