# 客服专项数据构建与下一轮实验

2026-09-28。用户决定不安排组员试玩或人工标注；本轮数据全部由AI起草并进行程序检查和独立子agent审查。没有下载新的公共语料、调用Jev、运行GPU评测或训练，也没有替换线上模型。本文记录下一轮训练的数据准备，不是新的训练结果。

## 为什么先做这一步

上轮139条项目业务集上，Qwen意图与Jev相近，差距主要在路由，尤其是普通说明问题被转人工或反复追问。因此先让训练输入与实际后端一致，并补充状态和表达边界；单纯延长第五轮训练不能弥补这些缺口。

此前402条合成客服测试共享训练生成器。此次仍是合成数据，不能声称已获得真实用户泛化证据。新挑战集在构造方式和用途上与训练集分开，但由同一AI编写并采用同一政策，仍可能共享偏差。

## 数据从哪里来

1. 当前Node客服的五个只读工具、输入适配、参数解析、守卫和会话状态。
2. 项目中申请、申请详情、材料补交、信用分页面的实际代码。页面存在某能力，不表示客服工具已经支持它。
3. `seedLoanProduct.js` 中的产品命名和字段，不读取数据库中的个人记录。
4. AI围绕上述能力编写新问法和短上下文。未把Jev或Qwen的预测当作答案。

源文件路径和文本哈希保存在 `data/support-curriculum-v1/source-snapshot.json`。所有路径相对项目仓库，不记录个人磁盘路径。申请号85011/85013/92021/92037均为离线夹具，不能直接用于真实数据库验收。

公开语料本轮仅作为后续候选：

|来源|适合补充什么|不能直接替代什么|
|---|---|---|
|[CrossWOZ](https://github.com/thu-coai/CrossWOZ)|中文任务对话的省略、纠正、跨轮指代；已有实验已用过其部分数据|贷款业务工具与权限标签|
|[MobileCS论文](https://arxiv.org/abs/2209.13464)|电信客服的自然口语与交互结构|本平台的贷款流程和动作规则|
|[CFLUE](https://github.com/aliyun/cflue)|其中银行客服意图分类可作金融领域补充评测|完整客服流程决策；其数据使用CC BY-NC-SA 4.0，不能按代码MIT许可直接用于商业训练|

本轮没有将这些新语料下载、改写或混入训练文件；避免将不同任务的一大批数据误当成业务路由训练。

## 当前动作协议与实验约定

不修改生产 `decision-v5.json`，继续使用 `tool/clarify/llm/human` 四路由，映射为后端的 `tool/clarify/answer/human`。拒绝和结束仍由后端规则处理，新增分类候选必须另行修改两端协议并做对照；知识检索尚不在当前四路由中。

|编号|本轮实验采用的约定|能力边界|
|---|---|---|
|P01|明确查“这笔/那笔”但无法确定单笔时先追问；明确要全部申请时查列表|这是本轮一致的实验标签，不代表先查列表供选择永远错误；不据模型输出来修改答案|
|P02|明确要求刷新才按实时查询；明确只解释刚提供的状态文字时回答|不添加后端未传入的 `facts`、记录新鲜度或未来工具结果|
|P03|一般操作说明可交回复模型；未知具体费用、拒绝原因等不能编造|路由正确不等于最终回复正确，也不等于知识检索已完成|
|P04|越权读取、篡改审批、代扣资金列为拒绝场景；合法申诉和实际争议列为人工|四路由不能直接表达refuse，此类样本保留作组件回归，排除四路由监督候选|
|P05|明确要求结束时close；仅感谢、稍等或仍有问题不能自动结束|close不进入四路由训练；自然结束表达未必被现有守卫覆盖|
|P06|现有状态释义工具只支持0/1/2；未知值先核对|App有其他状态用法，不能直接强迫当前工具解释全部状态；暂缓用于专项监督|

这些约定由AI为离线实验冻结，不等待组员审核，也不声称是已批准的生产服务政策。权限与记录归属仍由后端控制，不能由模型分类结果授予。

## 样本数量和用途

主集60张场景卡，30个场景族，每卡5个起草位置，共300个位置。部分卡共用同一句话对比不同状态，也有标点变体；规范化后只有272种不同消息。每个位置增加一组无关前置历史，形成600条输入。

|集合|原始输入数|场景族数|用途|
|---|---:|---:|---|
|训练池|360|18|过滤后再用于离线专项训练|
|开发池|120|6|检查错误、选择模型与配置|
|校准池|120|6|后续拟合置信度校准；本轮尚未拟合|
|新挑战集|90|18|另外编写，不做历史扩增，只允许评测|

主集按整个场景族隔离，同一卡的所有问法和前置历史变体不会跨集合。挑战集既不属于训练池，也不用于阈值调优。旧139条及旧第五轮402条继续称为已分析过的回归集，不能改叫新盲测。

这600条是验证数据构建流程和覆盖业务边界的起步材料，**不是600个独立用户，也不是已完成的大规模训练集**。后续扩充应增加独立场景族，不能靠换编号、增加标点或重复前缀制造规模。

## 自动检查做了什么

运行器直接调用相邻项目的真实 `modelInput`、`safetyDecision`、`toDecision`、`groundDecision`：

- 输入只保留短历史、服务端pending/selected状态及实际五个可用工具；没有截图、隐藏意图或未来知识证据。
- 构造期先检查ID、字段、状态所需历史、同输入标签冲突和跨集合重复。
- 在真实脱敏/规范化后再检查一次输入冲突，避免不同手机号被统一替换后留下不同监督答案。
- 检查标签能否映射成正确动作、工具和参数。无法映射的样本不悄悄改标。
- 对旧139条与旧402条进行规范化消息去重；匹配项不进入新候选。此检查不是语义去重，也不能证明基础模型预训练从未见过类似表达。
- 把规则路径单独记录。正确人工样本即使被规则处理，也可用于模型监督，避免过滤规则样本后人工类别消失；线上规则成功不能计为模型成功。
- 过滤后的训练、开发、校准三个集合均强制覆盖四路由和五工具，缺项即失败。各意图和类别数量仍不均衡，不代表覆盖全部业务组合。
- 原有输出目录拒绝覆盖，防止重建时破坏已冻结数据。SHA256按CRLF转LF后计算，避免Git跨平台换行导致内容未变却校验失败。

`runtime-inputs.jsonl` 中的 `mapped` 是**把建议标签强制送入适配器**后得到的可执行性检查，不是Jev/Qwen的预测；不能据此计算模型准确率。

当前过滤后的候选：训练298、开发120、校准110、挑战模型子集79。原始完整挑战90条始终保留，不因为现有协议/守卫失败就删除难题。计模型分数时使用有对应四路由标签的样本，并单独报告规则路径；计组件分数时用完整挑战集。挑战集另外包含未使用固定投诉/盗用关键词的资金争议和身份冒用疑虑，各5条；数量仍不足以证明风险场景已全面覆盖。

当前明确的守卫冲突：

- `F20-A-03` 两种历史：用户说“暂时不找人工客服，我只想看申请记录”，现有规则仍选人工。
- `X08-A-02`：用户说“不用替我扣钱，解释一下提前还款怎么选择期数”，宽泛规则误选拒绝。

它们保留为工程回归，不把预期标签改成误判结果。本轮准备数据，不修改这些生产规则，也不将这些失败称为Qwen能力问题。

## 文件和运行方法

入口目录：[`data/support-curriculum-v1/`](../data/support-curriculum-v1/README.md)。

|文件|用途|
|---|---|
|`场景卡.md`、`cards.jsonl`|60张业务卡、问法、标签依据和来源|
|`cases.jsonl`|主集600条，保留全部AI标签|
|`train/development/calibration-cases.jsonl`|分组隔离后的原始池|
|`train/development/calibration-candidates.jsonl`|经过可执行性、重复与覆盖检查的监督候选；仍为AI标签|
|`challenge-cases.jsonl`|90条单独起草的完整挑战集，只评测|
|`challenge-model-candidates.jsonl`|当前四路由可表达的挑战子集，不等于完整挑战分数|
|`eligibility.jsonl`|每条样本的保留/暂缓原因及规则路径|
|`runtime-inputs.jsonl`|真实适配器生成的输入和强制标签映射结果|
|`manifest.json`、`source-snapshot.json`|数据数量、来源、局限及可移植文本哈希|

`review.csv`只是复用现有工具生成的可选查看表，不要求任何组员编辑。它不包含场景族split和扩增元数据，不要通过旧通用导入器处理后直接拿去训练；修改应在本轮来源代码中进行，输出新版本，再完整检查。

在实验仓库运行已有版本检查（不加载模型、不联网）：

```powershell
.\.venv\Scripts\python.exe -m qwenlab.support_curriculum check --output data/support-curriculum-v1
# 同时核对相邻项目的能力源文件是否发生变化
.\.venv\Scripts\python.exe -m qwenlab.support_curriculum check --output data/support-curriculum-v1 --project ../uestc_Integrated_Design
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_support_curriculum.py
```

修改来源后用新目录构建，已有目录不会被覆盖：

```powershell
.\.venv\Scripts\python.exe -m qwenlab.support_curriculum build --project ../uestc_Integrated_Design --output data/support-curriculum-v2
```

构建需要Node、相邻后端已安装依赖，以及此前准备好的 `data/processed/v5/business-test.jsonl`。该旧测试原文不在Git中；新机器需要按第五轮数据准备流程重建。已有本轮产物的纯文件检查不需要这些依赖。构建失败会明确指出缺失，不会跳过去重检查。

后续需要运行完整挑战的模型对比时，在项目后端使用已有有界评测器，输出到新的结果目录：

```powershell
npm run benchmark:support -- --cases ../../qwen/data/support-curriculum-v1/challenge-cases.jsonl --qwen-root ../../qwen --output ../../qwen/results/support-runtime-v1/challenge-run-01 --repeats 2 --max-jev 180 --allow-jev
```

该命令会产生Jev API调用，必须在Qwen常驻服务和Jev环境配置可用时执行。本轮没有执行它。

## 下一轮训练如何继续

1. 以当前规则明确、输入可表达的候选为种子，继续增加新的训练场景族；保留本轮开发、校准、挑战族不混入训练。优先补普通解释/人工、正常查询/追问的边界，而非无差别增加公共意图样本。
2. 专项训练继续采用已验证的2B NF4 QLoRA配置；混入一部分旧训练数据维持既有能力，不能混入旧测试。先用固定小预算判断方向，再决定增加数据和训练步数。
3. 使用同一输入、同一政策比较原始Qwen、当前step-7110和新适配器；选择只看开发集。校准使用单独校准池，不能用挑战集调阈值。
4. 模型冻结后再看新挑战集，并报告按场景族平均的效果、工具联合正确率、过度转人工和人工漏转；完整组件与强制模型分类两种口径分开。
5. 同时测P50/P95，保持真实三次前向的调用方式；数据微调不自动解决三次前向的耗时。新模型未证明收益前，云端继续用Jev，本地保留切换对照。

本轮没有训练损失、新权重、微调收益或过拟合结论，也不宣称数据越多就必然更好。全部由AI完成数据工作后仍可继续实验，局限如实记录即可，不需要等真实用户或人工参与。

## 本轮验证记录

新增10项数据构建校验测试；连同已有服务、讨论稿和复核导入测试，共29项通过。正式数据文件哈希与当前项目源文件检查通过，461个发布文件扫描通过；没有导出个人绝对路径、密钥、模型权重或学习笔记。

子agent初审指出真实脱敏输入可能冲突，以及过滤后开发集缺少澄清类别；两项均修复后再审通过。新增挑战还保留现有守卫误判及自然结束未覆盖，未按运行结果改标签。本轮没有模型预测，程序映射检查通过不能作为模型准确率。
