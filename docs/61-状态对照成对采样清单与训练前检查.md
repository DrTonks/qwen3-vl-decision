# 状态对照成对采样清单与训练前检查

承接报告60，本轮将136条复核候选编成了**可重放的400步、每步8条业务样本清单**。新故事的每个状态在前200步和后200步各出现一次；原有当前无知识库服务的10对对照也在前200步全部补齐。清单已经生成、冻结并通过独立代码审查，**未运行GPU训练，未产生新的模型成绩**。

## 1. 目标与本次控制的变量

希望模型学到“相同业务提问，可信状态变化时动作应变化”，而不是继续增加与业务无关的语料。训练候选仍为AI合成并经独立AI复核，不标成人工数据。采用常规动作交叉熵及原工具监督损失，不新增成对损失。

基线是报告58已完成的未登录覆盖方案，沿用其400步、8条有效批次、2条微批次和2048 token上限。本轮随机数只用于离线采样，seed为20261005；未来模型初始化仍应使用原执行设计中的20261004和相同初始LoRA参数哈希，二者不要混淆。

每个被替换位置同时保持以下属性：业务层、认证真假、是否有知识库、动作标签、工具标签。因此，前200步、全400步乃至任意训练前缀的这些类别计数均不变，类别所处的学习率位置也保留。**文字、可信状态具体值、故事分布和重复次数仍改变**，这是新对照数据与曝光策略的联合实验，不能声称只改了数据数量。

新增272个位置占总预算8.5%；另外9个位置用来补原有锚点。旧清单有4个锚点全程没出现、另有5个只在后半程出现，所以前200步共补9个，不是额外新增9条语料。

总体去重样本从2498增加49：原有91条被完全替换，加入136条新样本和4条旧清单未见锚点。未登录去重样本减少42：40个新未登录候选各见两次，另外两个旧未登录锚点在前半程补入后也形成重复。这是新设计明确允许的变化，不能沿用旧方案“未登录样本完全不重复”的表述。

业务层也仍为当前Node1440、当前组件480、计划知识库800、未登录480。新样本只替换相同层/认证/知识库/动作/工具的位置，计划知识库和当前组件层没有新候选替入。所有旧锚点已存在的位置都被保护。

更细的追问缺项次数并非完全相同：共6个`error_context`和4个`request_details`位置转为`authentication`监督，其他替换的缺项类型相同。算法优先找相同缺项，再优先替换重复旧行，并要求每半程旧的每个缺项桶至少留一条；找不到合法位置就失败，不会放宽上限。**保留桶不等于保留桶内全部业务多样性**，91条被挤出本轮曝光的旧样本需在后续旧业务回归指标中监测。

## 4. 成对覆盖及计算预算

|对照范围|基线前200步完整对数|新前200步完整对数|基线400步完整对数|新400步完整对数|
|---|---:|---:|---:|---:|
|新增单字段对照|0|88|0|88|
|新增状态码缺失文字对照|0|8|0|8|
|旧当前无KB对照|2|10|5|10|

新96对在后200步也都再次覆盖。88对严格对照与8对改变文字的补充继续分开统计；同故事全部留在训练侧，不拆到验证集。正反样本不要求出现在同一微批次，仍是逐样本常规CE监督，没有把“同阶段见过两侧”冒充成对损失。

|按真实token长度汇总|基线|本轮|变化|
|---|---:|---:|---:|
|动作与真实工具提示，无padding|2,029,011|2,029,427|+416，约+0.0205%|
|按实际微批次补齐后|2,054,945|2,054,924|−21，约−0.0010%|

长度来自已冻结的真实本地tokenizer结果，新候选模型输入没有更改；迁移只调整训练池的split/cohort/input_layer元数据。预算非常接近，但不是完整FLOPs或墙钟耗时测量；不同内容、硬件负载和训练中间状态仍影响速度。不能据此给出新模型的准确率或延迟结论。

## 5. 工程实现与核验

- 配置：`configs/financial-state-pair-schedule-v1.json`。
- 清单生成与校验：`src/qwenlab/financial_state_pair_schedule.py`。
- 新增样本：`data/financial-state-pair-study-v1/schedule-v1/additions.json`，136条。旧13242条训练池仅引用，不复制或改写。
- `plan.json`：400步逐条样本ID及200步前缀。
- `exposure-ledger.json`：3200条曝光的步数、微批次、样本/故事ID、行哈希及重复次数。
- `replacement-ledger.json`：281个替换位置的新旧ID、类别及缺项变化。
- `pair-exposure.json`：每对实际出现的步数和前/后半程完整覆盖。
- `summary.json`、`manifest.json`：统计和冻结依赖。源闭包包含前置清单、候选审核证据、配置、代码和测试；实际Node依赖仍由候选核验器检查。

11项CPU测试通过，覆盖逐位置类别、旧锚点保护、每半程候选一次、元数据迁移不改输入/标签、行序变化不影响结果、未知行/错误前缀/改预算/无合法替换位置等拒绝路径。独立进程设置不同`PYTHONHASHSEED`后逐字节重放通过。

独立审查另行重算采样、逐项曝光账本和token总量，结果与冻结文件一致，未发现阻断问题。审查证据见[成对清单独立复核](evidence/financial-state-pair-schedule-review.json)。

## 6. 下一阶段的具体目标

数据与采样前置检查已具备继续条件。下一阶段是为这份清单接好独立执行入口，然后依次完成：

1. 新运行命名空间，读取旧池+136条新增行；继承原始0.8B底模、初始化、LoRA、优化器、400步学习率、CE损失及所有原验收门槛。**不能直接把新清单传入冻结的旧preauth运行器**，它只验证旧池和旧采样规则。
2. 独立代码复核后进行25步试运行，在第12步真实保存、退出、恢复到第13步；试训适配器丢弃，验证optimizer/RNG/采样游标和单GPU互斥。
3. 全新LoRA正式训练固定400步；200步仅诊断，不因单次波动早停，不自动延长。逐项比较报告58基线的追问召回、未登录误用、工具联合与旧业务回退。
4. 只有通过原门槛才进入校准及保留评测。已有开发集已反复使用，不能宣称其为独立泛化证明；不拿开发或最终错题继续生成训练样本。

本轮未启动上述试训或正式训练，未调用Jev、未部署、未提交或推送。此处没有新结果可以宣布胜过Jev/V5，也不承诺样本结构修正必然改善模型。
