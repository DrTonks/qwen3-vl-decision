## 此次补齐的重点

1. **真实工具范围**：对照项目`后端/services/customerSupport/tools.js`。产品工具返回目录、额度、标签等，不含实时利率；申请工具不返回还款明细；信用工具读取已有信息，不生成新的授信结论。避免把缺失能力标成可执行查询。
2. **容易混淆的动作**：受害者求助与主动伪造、合法申诉与篡改审批、感谢后继续与明确结束、平台具体条款与一般概念、查本人记录与查公开文档。
3. **依赖上下文的决策**：同一句“我想看最新的”，前文是产品目录时查询工具，前文是平台上传规范时检索；“这件事帮我处理一下”，前文是身份被冒用时建议人工，前文是要求冒用别人身份时拒绝。
4. **能力与事实边界**：未知平台规则不编造；没有查询工具不从知识库推断个人记录；未接通人工时human表示建议协助，不生成虚假转接结果或工单。用户不愿转接也不应被强制转接。

多数输入继续采用规划中的`planned-kb-v1`，不代表本轮已接通知识库。当前后端五个工具在execute入口统一要求登录，因此候选遵循当前实现；这不是宣称公开目录/状态释义天然必须登录。八动作数据契约仍不直接兼容旧四路由训练器和推理服务。

## 审查与验证

独立审查agent审查了旧试点、公开部分、A批全部场景及构建校验器；A起草agent另行审查未由其起草的B批和主agent状态对照。最终可追溯记录见数据目录`agent-review.md`。

审查推动的确定性修复：

- 申请ID改为完整数字匹配，拒绝把624179中的62417当作完整编号。
- 识别当前“申请编号/编号/单号”与历史选中ID的显式冲突，避免继续查询旧对象。规则并未穷尽自然语言实体理解，不能代替人工和后端归属验证。
- 标注字段、缺失槽位、工具参数加强类型检查；拒绝Python中可与0/1相等的布尔值冒充整数参数。
- 公开请求“有什么活动要举行吗”可能是在问平台优惠，已排除；表达异常的“电报上的交通”也已排除并补选其他原训练行。仅凭公开意图标签不能决定本平台动作。
- 两条询问申请记录与信用评分“有什么区别”的样本从clarify改为answer；保留原话和场景组，不为了维持类别配额改写话语。

验证结果：19项CPU单元测试通过；1,020条无重复规范化完整输入，与受保护评测消息无标准化精确重合。58个受保护文件、13,014个标准化评测消息参与隔离检查，源文件与原试点哈希核验保持不变。唯一报告的金融文本近似项仍是原试点“状态码1或2是什么意思”，已保留`needs_discussion`并排除在1,019条候选统计外。

隔离检查覆盖当前消息字符串与金融文字近似，不等于对历史对话、语义模板或全部来源关系证明独立。任何已用来训练的旧来源都不能被重新命名为新盲测。

在qwen仓库根目录执行：

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.financial_expansion validate
.\.venv\Scripts\python.exe -m qwenlab.financial_expansion render-review
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_financial*.py' -v
```

`validate`只读；`render-review`在检查通过后重写阅读版，不更改标注或初始哈希基准。`build`只供首次生成，已有目录会拒绝覆盖。仓库只保存相对路径和来源元数据，原始语料缓存、密钥和模型仍由既有.gitignore排除。

## 能说明什么、下一步是什么

这批数据比180条试点增加了覆盖和可追溯性，但尚未证明模型会变好。部分新样本使用“只问概念”“不是查询”“按正式文档”等明确限定词，域外公开文本也有翻译口吻；全部redirect的大部分来自公开源，其他动作多由助手起草，存在来源风格与标签相关的捷径。不能只在同样风格的数据上得到高分就称为泛化。

下一步目标应是**训练前冻结一份可信的数据契约与独立验收方案**：先统一能力缺失、多意图和人工建议的动作政策；将剩余歧义隔离；补自然省略、更多跨动作状态对照，并用不同来源/场景设计新开发与最终测试集。对近义家族和公开原文改写继续合组，再做训练导出。首轮试训验证标签和工具选择是否学会，之后才决定继续扩量或对比更小模型。当前1,020条不含新独立测试集，也不包含图片。
