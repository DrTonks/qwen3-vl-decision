## 旧标签怎样迁移，哪些没有重审

旧版本的`handoff_connected`含义不够清晰。本轮凡是`true`的关联组全部隔离；保留样本明确进入新场景：`handoff_available=false`，会话`handoff_status=none`。这是新版本设定，不是声称旧false等价于连接器不可用、旧true等价于已建单。

迁移保留认证、当前申请编号、状态码、历史、工具名单与KB能力差异；`planned-kb-v1`映射未来档案，`current-no-kb-v1`映射当前档案。472条明细查询参数、256条状态解释参数均与显式可信状态一致。

审查分两层：

- 沿用文档45的184条逐条审核建议。原11条修订中10条实际进入本版；另1条`FIN-R4-crosswoz-train-11912-2`因关联组隔离而未发布，不能绕过整组隔离。
- 独立agent对全12,235条执行政策风险筛查，再完整阅读336条命中项，255条保留、81条隔离。新增风险包括合法个人写操作误标普通回答、能力询问与具体代办无法唯一分辨、旧人工状态含糊。隔离通过来源ID、场景组和父子来源连接传播，不只删除命中行。

**没有把11,756条全部按新政策重新逐条语义审核。** 多数保留原审核，仅完成结构迁移；筛查未命中也不等于没有语义问题。新`review`保留旧审核来源，区分本轮定向复核与修订提案，`human_reviewed_current_version=false`。新评估同样是AI编写、独立AI复核，不能标为真人标注。

## 评估如何保持独立

作者只按共享政策、Flask输入合同与实际Node五工具字段编写新故事，没有查看旧训练语料、旧评估或模型错题。另一agent完整阅读384条输入、历史、可信状态、能力与标签，修正14条缺少“申请编号/状态码”对象说明的文本；最终检查另发现1条新编号与可信state不一致，已修正输入并重新签核。动作和工具标签未为了模型表现而调整。

来源组不跨开发、校准、最终三个分区，也不与训练组相交。消息和历史进行数字归一化、去空白检查；训练—评估完整文本相同、消息相同、近似文本，以及评估跨分区同文检查均为0命中。近似检查只对每题字符三元组最接近的20项计算SequenceMatcher，阈值0.86，**不是穷尽语义去重证明**。

每个评估分区覆盖八动作和五工具，human/refuse/tool均至少12条。但仍有明显局限：

- 同一故事4条相关变体、同类规则跨组出现，不能按完全独立同分布样本解释成绩。
- 部分文本直说“只问能力”“请人工”，比真实用户含糊表达更容易。
- 开发集redirect只有4条、close只有6条、状态工具只有3条；一题会改变25、16.67、33.33个百分点。高分或零错均不能单独证明稳健性。
- 当前服务开发子集human仅14条，全部正确仍不足以证明真实召回稳定达到95%。后续报告需同时给分母、区间与按故事组bootstrap，不能只报百分比。

这是受控的**契约回归与能力测试**。通过后仍需后端鉴权/参数/降级验证；要宣称真实业务泛化，还应另做口语、省略、长短历史及截图等外部盲测。本轮没有图文数据或多模态成绩。

## 下一轮训练方案与明确边界

[实验设计](../configs/financial-service-v2-study.json)已定稿，状态是`frozen_design_executor_pending`、`training_enabled=false`。它是可审查的设计，**不是已经可运行的训练执行器**。训练候选仍保持`training_eligible=false`，防止被旧执行器误读。

建议下一阶段实现新执行器并审查后，从官方**Qwen3.5-0.8B原始权重＋全新LoRA**开始；不用上一轮失败候选续训。继续沿用r=8、alpha=16、dropout=0.05、BF16基座、FP32 LoRA、语言模块q/v及线性注意力投影；仅更新LoRA。学习率5e-5、预热100步、micro batch=2、effective batch=8；每行每轮出现一次，不靠复制数据掩盖当前服务比例。

固定预算两轮：每轮ceil(11,756/8)=1,470步，共**2,940步**。第200步只诊断，不因为一次波动立即结束；第1,470/2,940步按开发门槛选候选。不自动追加第三轮，不从开发/最终错题生成训练数据。数值异常、运行故障或用户暂停另行处理。

原总体门槛保留：宏F1比同提示原始模型至少高0.01，各动作召回至少0.8、human召回至少0.95，人工漏判/误拒绝不比同提示原始模型增加，无不可用KB检索，动作＋工具联合准确率和状态工具准确率至少0.9。额外单独检查当前服务human/误拒绝/工具能力、登录前不得调用工具、不得选择不可用工具，避免总体分数掩盖当前能力退步。小分母达标只是实验条件，不能当部署证明。

训练损失明确为`sum(CE_action + 0.75 × I(真实动作=tool) × CE_tool) / B`，B是有效批次实际原始业务行数，末批也按实数计算。工具损失分母不是tool行数，且不把每个tool行再除以1.75；这沿用旧损失约定，tool行有意承担额外监督，所以同等采样次数不代表同等总损失权重。不能把一个tool样本拆成两行后悄悄改变采样比例。真实推理仍先选动作，只有预测tool才做工具选择，联合成绩不能使用真实标签替模型选择动作。

通过开发门槛才在96条校准集选温度和阈值；固定候选与阈值后，160条最终集只做一次模型评测。没有合格候选则停止，不读最终模型成绩补救。置信度只是候选偏好，需要校准；拒判/转交比例必须与接受部分准确率一起报告。

执行顺序：新执行器与暂停恢复审查 → 训练集专用50步耗时/显存探针（之后丢弃探针LoRA）→ 原始模型同提示开发基线 → 从全新适配器进行固定两轮 → 开发选择 → 符合条件时校准和最终 → 独立端口真实模型服务验证。旧提示测得的Jev/Qwen/V5结果只作历史参考，不能拼入新版同口径表；本轮配置API预算为0。需要新版Jev基准时应另行确定新输入与预算。

**时间尚未实测。** 旧0.8B探针约2.65秒/步，仅作粗算：2,940步纯训练约130分钟，不含新提示差异、评估、保存、加载和系统负载。新执行器完成后用50步探针重新给预计分钟数，不能把旧数当本轮承诺。

当前服务只有574条是可见短板。先通过分场景基线和有限预算检查它是否学会能力差异，若不足，应在下一数据版本补充多种当前能力下的表达和状态变化，并独立复核；不能把全部未来KB文本简单批量换成answer，或在看到测试错题后补相同模板。

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.financial_service_v2_data validate
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_financial_service_v2_data.py
.\.venv-qwen35\Scripts\python.exe -m qwenlab.financial_service_v2_preflight
```

这些命令无需数据库、Jev或GPU训练。token检查依赖已准备的`.venv-qwen35`和本地模型tokenizer。构建与冻结命令用于一次性生成，已有manifest时拒绝覆盖，不应当作每日重复命令。

若要人工修改，**先复制成下一版草案**，按ID记录原标签、新标签、完整上下文理由，重新审核后再发布新版本；不要直接编辑冻结JSON后沿用旧审核或SHA。当前报告与数据均保留AI来源，不把没有发生的人工复核写进去。
