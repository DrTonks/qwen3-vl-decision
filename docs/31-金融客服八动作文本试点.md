# 金融客服八动作文本试点

日期：2026-09-29。已生成180条文本候选、93个来源/场景组；其中179条保留为草稿候选，1条标注有歧义暂缓。尚未训练、调用模型评测或改变生产配置。这批数据的用途是检验动作规范和数据工程流程，数量与难度还不足以验证训练收益。

## 交付与数量

数据目录：`data/financial-actions-text-pilot-v1/`。

|动作|全部条数|暂缓后候选|典型含义|
|---|---:|---:|---|
|clarify|24|23|缺少对象、原文或认证信息，先补充|
|retrieve|26|26|查平台正式文档，尚不生成事实答案|
|tool|26|26|调用白名单工具查询实时业务记录|
|answer|23|已有充分文字信息、一般概念或诚实说明能力限制|
|human|21|争议、账户风险或明确人工需求，需要升级|
|redirect|20|无关但正常的请求，引导回贷款服务|
|refuse|20|越权取数、伪造材料、篡改审批等不允许的操作|
|close|20|明确结束本次咨询，不取消贷款申请|

来源包括：旧业务训练来源迁移86条、公开MASSIVE训练原文重新标注20条、由其结构启发的贷款改写8条、新起草文本54条、6组状态/能力对照12条。改写保留公开原文、父ID和授权信息；它们是助手改写，不是真实贷款客户原话。原文与改写同组，今后不能分到训练和测试两边。

全部来源本轮标签均为助手起草/重新标注。旧业务来源曾经人工复核，不代表本次八动作新标签获得人工确认。`human_reviewed_current_version`全部为false。

## 结构与工程边界

模型只允许读取`input`。动作、工具参数、依据放在`annotation`，来源放在`provenance`，复核状态放在`review`。编码入口`financial_pilot.serialize_input`排序JSON键及无序工具/集合列表，减少工具枚举顺序的偶然影响。此改动不追改旧实验。

这是新八动作契约，**不能直接塞进旧四路由训练器或当前推理服务**。工具选择仍有独立字段；八动作选中tool之后，未来可再选具体工具，或用独立工具头联合预测，本轮尚未实现训练映射。

多数样本采用`planned-kb-v1`：假设存在公开贷款服务文档和隐私政策集合，但并未编写这些平台条款或接通检索。其余动作也使用相同能力配置，避免“有知识库就必选retrieve”的字段捷径。另有无知识库对照；该情况下answer仅表示如实说明无法核实，不能编造规则。人工接口统一标记未接通，human是需要升级的决策，不是已建工单。

## 自查结果和局限

- 180条均通过结构、参数、来源分组、重复输入与评测字符串隔离校验；10项CPU单元测试通过。
- 核对58个受保护来源文件，覆盖13,014个标准化评测消息；精确匹配0。旧数据及冻结评测文件哈希未变化。
- 有1条与旧评测文字近似：`FIN-P1-F13-A-01-base`，“状态码1或2是什么意思”。其旧标签为澄清，但也可能要求解释两个状态，已标记`needs_discussion`。候选统计排除它，不通过改写这条评测近邻来增加训练数据。
- 174个不同标准化消息、180个不同完整输入：有意保留同句不同状态。6组对照中5组动作改变，公开文档登录对照的动作保持retrieve，用来检查无关状态不应改变决策。
- 字符串去重不等于语义独立，也未证明不存在其他跨来源近义/模板重合。原训练来源不能改名成为新独立测试集。
- 新生成部分用语偏明确，尤其拒绝、结束、检索；仅做标签试点。下一批须覆盖口语、隐含诉求、否定表达、相似但不同动作及短多轮状态，避免模型只记“结束”“正式文档”等词。
- 暂不将多意图冲突强行标为一个动作；先隔离讨论。这里也没有图片、真实用户分布、真实工具返回和完整多轮执行成绩。

## 复现与下一步

在仓库根目录PowerShell运行：

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.financial_pilot validate
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_financial_pilot.py -v
```

`build`仅用于首次构建；目标目录存在会拒绝覆盖。编辑主文件后运行`render-review`可验证并更新阅读版；不更新初始manifest基准。若`cases_match_initial_manifest`为false，表示内容已变，必须重新复核再冻结版本，不能继续引用旧统计。详细编辑说明见标注指南。

下一部分建议先扩到约1,000条、至少200个独立场景组，仍只作为候选：优先补tool/retrieve、clarify/answer、human/refuse、close/礼貌回应边界，再扩大公开域外样本。1,000是下一阶段目标，不是已经可训练的有效数量。先锁定动作和能力契约，再做独立开发/测试来源、训练导出、模型基线与小规模试训；不直接用这180条证明八动作模型已经改善。
