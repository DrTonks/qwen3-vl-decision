# 金融客服补充候选扩充与全量复核

2026-10-04，承接报告49—50。**1,678条构建候选经独立AI审核及全量校验，最终接受1,486条、412组，隔离192条、49组。** 这轮未开始新的训练、推理API调用、部署或提交推送。复核候选不等于训练发布，更不等于模型效果已经提升。

## 为什么继续补数据

上一轮新契约训练两轮均未通过门槛，第二轮开发表现下降。增加相同模板的曝光不一定有益，本次优先补当前后端能够执行的客服场景、明确参数与缺失参数、能力咨询与实际操作、合法请求与违规请求的区别，并让输入经过实际Node生产逻辑。

两个作者分别从现有八动作政策和五个只读工具规范创作760条，共1,520条、382个来源组，每组最多4条；381组包含不同动作对照。新增内容有204条携带可见历史。加上首批已独立AI复核的158条，构建快照合计1,678条、461组。来源组是作者定义的关联边界，不等于461种完全独立的真实客户需求。

新数据为原创AI合成，没有把旧开发/校准/最终测试错题改写成训练数据。作者和标签复核者不读取历史评测题面或模型预测；历史来源由独立盲筛脚本只读比较，返回本批候选ID与统计。新增数据尚未由用户人工复查，因此始终保留 `human_reviewed=false`。过去其他数据集的人审记录不适用于本批。

## 自动验证和隔离范围

独立复核按实际投影后的输入判定，不只读作者原文。发现的问题分层记录，整组隔离，不在本轮修改后端或改稿追求通过率：

|问题类别|本批例子|处理含义|
|---|---|---|
|动作标签与实际用途冲突|编造产品名称用于报账，却标普通回答|实际造假请求不能因出现“产品”就当业务问答|
|工具字段越界|要求历史产品名称，但工具仅关联当前产品名称|不能把当前查询结果冒充历史快照|
|枚举与缺槽混淆|明确给出不支持的状态码，却要求补状态码|不支持值不等于信息缺失；有歧义先隔离|
|参数解析与语义不同|中文数字编号、唯一历史编号被忽略|属于输入适配问题，不能教模型忽略可见信息|
|脱敏后丢失答复依据|邮箱变成`[邮箱]`仍标为可复述地址|模型不能恢复被删除的事实|
|当前无处理能力|要求修改个人资料，只因缺字段就追问|补齐字段也不产生写能力，clarify/human需唯一判定|
|认证与能力缺失混淆|未登录且可信工具列表显式为空|Node并不因未登录自动过滤工具；不能凭作者意图假设登录后恢复|

这不是宣称所有对应后端行为都应修改：例如脱敏有其目的，数据应尊重最终可见信息；澄清与人工的边界有时需要先明确产品策略。只有明确的工程缺陷才进入独立修复和回归流程。

- 1,678条结构及政策校验通过，1,520条新增输入经过真实Node导出。重放验证所有派生文件、六个后端源码指纹与源数据哈希，首批继承项另验证原审核链；原C08隔离组没有返回。
- 使用本地Qwen3.5-0.8B tokenizer检查全部1,678个动作输入及348个工具输入：最长分别544和587 token，平均498.96和551.80，均小于2,048，无截断。没有加载模型权重或占用GPU训练。
- 正文数字规范化发现12对重复，仅凭正文不能推断标签冲突，因为认证、历史与工具能力可以不同。完整可见输入若跨组完全相同，发布时保留较早组并隔离后组。
- 历史盲筛命中保留集10条、历史训练池12条，二者可交叉；按组扩展后共11组、40条隔离。连带隔离项自身不一定命中。首批中也有2组、4条在此次更广筛查下被隔离，旧首批包保持原样，本次接受清单为新的选择结果。

这些索引条目包含同一题在不同实验版本的快照，**不能当成117,596条独立样本**。具体路径、读取规则和来源指纹在 `configs/financial-supplement-heldout-index-v1.json`；脚本检查字节、行数和读取规则后才筛查。NFKC、数字统一及字符二元组Jaccard≥0.85用于正文和有顺序的历史上下文匹配；没有词面命中仍不能证明语义无重合。保留集匹配用于排除数据，未用于模型选型或对命中句子换词补写。

独立工程复核修复了两处发布漏洞：仅信任保存的盲筛摘要可能漏查来源；只检查分词报告状态可能漏掉工具子任务。现在发布时重新执行全部盲筛并逐项比较完整报告，同时重新编码全部动作/工具输入。38项持久化单元测试通过，涵盖源/审核哈希、漏条重复、整组隔离、完整输入去重和报告篡改拒绝。最终发布实际执行Node、分词和盲筛重放，产物全部来源/文件SHA再次验证通过；工程结论为`pass_with_scope_limits`，没有未解决代码发现。范围限制包括词面筛查不能证明语义独立、独立AI审核不等于人工审核或实际业务泛化。

复查时以用户整句话和可见上下文为准，检查“当前能够做什么”。不能将合法但尚未支持的个人业务错误标成refuse，不能把引用的违规话当实际请求，也不能因为句中有“谢谢”就忽略未完成的问题。当前没有正式知识集合时，不得标retrieve。工具参数必须能从模型所见信息成立，同时与实际后端解析一致。

请复制作者源并建立新构建版本后修改；不能直接编辑派生候选或将 `training_eligible` 改为true。修改任何绑定内容会使旧审核失效，必须重新复核、重放和筛查。`build-v1`保留创建时待审状态，当前结论以`reviewed-v1`为准。

## 可复现命令

在qwen根目录执行；后端为相邻仓库，不需要启动数据库或HTTP服务。分词环境已在D盘准备好。

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m unittest tests.test_financial_supplement_expansion tests.test_financial_expansion_overlap tests.test_financial_expansion_release
.\.venv\Scripts\python.exe -m qwenlab.financial_supplement_expansion verify --backend ../uestc_Integrated_Design/后端 --out data/financial-supplement-expansion-v1/build-v1
```

下列是**新版本**的构建顺序示例，输出必须不存在；独立审核也必须对应新版本的完整候选SHA与逐条源SHA，不能复用v1审核。

```powershell
.\.venv\Scripts\python.exe -m qwenlab.financial_supplement_expansion build --backend ../uestc_Integrated_Design/后端 --sources data/financial-supplement-expansion-v1/batch-a.authoring.json data/financial-supplement-expansion-v1/batch-b.authoring.json --out data/financial-supplement-expansion-v1/build-v2
.\.venv-qwen35\Scripts\python.exe -m qwenlab.financial_supplement_expansion audit --backend ../uestc_Integrated_Design/后端 --out data/financial-supplement-expansion-v1/build-v2
.\.venv\Scripts\python.exe -B scripts/screen-financial-expansion-overlap.py --candidates data/financial-supplement-expansion-v1/build-v2/candidates.json --output data/financial-supplement-expansion-v1/build-v2/blind-overlap.json
```

每个独立标签review必须覆盖各自完整批次，含 `candidate_sha256`、`policy_sha256`、`independent=true`、`human_reviewed=false`、`evaluation_data_read=false`，逐条记录 `id/source_row_sha256/reviewed_action/decision/reason`。非接受决策隔离整个组。工程review还绑定构建器、筛查脚本和发布脚本字节。

为build-v2另行完成并保存`label-review-a-v2.json`、`label-review-b-v2.json`、`code-review-v2.json`之后，才能运行下面的审核包命令。这里的v2审核文件是待新建文件，不能复制旧文件改名冒充；当前v1证据文件名见上文链接。发布器会再次重放Node、实际分词和全部盲筛，因此**必须使用包含本地tokenizer依赖的`.venv-qwen35`**。该命令不运行模型，不会授予训练资格。

```powershell
.\.venv-qwen35\Scripts\python.exe scripts/finalize-financial-expansion.py --build data/financial-supplement-expansion-v1/build-v2 --backend ../uestc_Integrated_Design/后端 --reviews docs/evidence/financial-supplement-expansion-label-review-a-v2.json docs/evidence/financial-supplement-expansion-label-review-b-v2.json --code-review docs/evidence/financial-supplement-expansion-code-review-v2.json --screen data/financial-supplement-expansion-v1/build-v2/blind-overlap.json --out data/financial-supplement-expansion-v1/reviewed-v2
```

审核每条必须恰好出现一次，最终包验证候选SHA、政策SHA、每行源SHA、标签和审核代码版本；缺条、重复、旧审核绑定均拒绝。原历史索引中部分原始语料/处理快照被Git忽略，换电脑重放需要先按原数据流程恢复完全相同的文件，不能只凭本仓库的审核摘要跳过缺失来源。

## 下一步的边界

本批仍为候选，不能直接给旧执行器追加长训。下一阶段应先冻结混合采样和曝光上限：当前真实Node输入为主，组件鲁棒性、未来检索与未登录场景单独计数；同时保留旧业务回放，避免新场景挤掉基础能力。新旧来源组不能跨训练与评估混用，开发/校准/最终测试职责继续分开。

例如仅将本批与原11,756条池拼接，当前服务最多为(574+1,125)/(11,756+1,486)=12.83%；即使新补充池75.71%是当前服务，整体均匀洗牌仍会稀释它。因此下一步优先冻结“分场景、分来源组采样”的有限对照，而不是马上扩到更多条。上述只是未重新筛选旧池前的比例演算，不是已发布的训练清单。

先做有限预算的对照探针，再根据冻结门槛决定是否长训；应同时报告八动作、工具联合、人工漏判/误拒绝、不同cohort和真实服务输入的结果。候选增加、审核通过、分词变短均不能替代这些实际测量。少数动作仍较少，合成文字也较整洁，需要在采样、自然表达和独立评估中体现局限，不能为了凑平每类数量而机械复制。
