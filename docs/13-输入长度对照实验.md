# 输入长度对照：Qwen 与 Jev

## 要回答什么

此前不同轮次的提示和样本发生变化，不能直接用旧的382ms与新的566ms计算模型对输入长度的敏感度。本实验固定当前第五轮模型、政策、用户诉求和业务状态，只增加与当前事项无关的历史记录，比较两种调用方案随输入增长的延迟和决策变化。

这不是微调或新模型选型，也不把API答案用于训练。

## 已完成结果（2026-09-27）

全部288次请求完成，Jev实际调用144次，失败0，无重试；Qwen候选输出层没有回退。测量流程约4.27分钟，包含本轮加载/预热等流程时间，逐请求统计排除了本地加载和预热。

**本次支持“Jev调用方案对这类输入增长更不敏感”。** Qwen最长档中位耗时约为原始档3.34倍；Jev各档中位数约480～500ms。第一、第二、第三轮中，Qwen最长档分别为1956/2016/1934ms，而Jev为484/484/504ms，趋势不是由单个慢请求造成。

按每个问题计算最长−最短再平均，Qwen增长约1372ms，Jev约17ms；两者增长差约1355ms，按问题bootstrap的探索性95%区间为[1311,1400]ms。这个统计与表格中“两个总体中位数相减”口径不同，数值不必相同。不能从远端耗时平稳推断它没有处理长输入或用了某种特定架构；报告的输入token用量确实随长度增加，但内部处理/缓存机制不可见。

Qwen最长档有1/12个独立问题意图从application_detail误判成repayment，三个重复均错；它包含历史指代和用户纠正，路由human及工具none仍正确。Jev在每档都漏转同一个必须人工的问题，三个重复均漏转；这些小样本不能代替先前402条测试的准确率。完整错误和逐轮速度在[诊断记录](../results/joint-v5/length-benchmark/diagnostics.json)。

这意味着接下来应优先研究**限制传入决策模型的历史、提取当前业务状态，以及减少三次重复前向**，每次同时回归准确率和人工漏转。不能直接删除看似无关的原始历史，因为指代、纠正、工具返回仍可能是必要证据；也不能为追求速度采用此前漏转增加的未训练动作合并方案。本次尚未实施这些优化或追加训练。

## 固定设计

- 从第五轮测试中固定抽取12个问题：tool、clarify、llm、human各3个，12个不同表达组。抽样种子20260928。
- 每个问题设置4档：原始输入、追加约256、640、1024个Qwen token。新增内容是先前已结束的纸张、植物、展览阅读记录，放在原历史之前；不改最新消息、原历史、登录状态、工具、政策或标签。
- 以完整句子追加，因此实际新增约259、645～648、1032～1035 token。最长单次前向1860 token，未截断。
- 每档重复3次，48个不同输入，共144次Qwen请求和最多144次Jev请求，无自动重试。Jev发生严重权限/余额/限流/版本错误时停止，连续3错或累计6错也停止。
- 每轮随机化问题和长度顺序；每对输入交替先调用Qwen或Jev。保存全部逐请求数据，不择优删除慢请求。

## 两方实际做了什么

Qwen为NF4 Qwen3-VL-2B-Instruct＋第五轮step-7110 LoRA，使用已验证的候选输出层裁剪。每个请求串行执行意图、路由、工具三个前向，包含分词、GPU前向及概率回到CPU。四档长度分别预热，候选行首次与完整词表的一致性检查在计时外；加载不计时。

Jev使用已有API密钥，一次HTTP请求同时提出上述三个问题，成功响应必须是jev-1.13.0。计时包含序列化、网络及服务处理。API失败保留错误类型和HTTP状态，不保存凭据或含请求对象的异常正文。

实验只衡量单请求端到端决策延迟，不衡量并发吞吐或最后给用户生成完整回复的耗时。两方模型和服务器不同，不能把结果解释为相同硬件的架构优劣。

## 指标与正确解读

每档36个请求，报告成功请求P50/P95，失败单独计数并在准确率中算错；准确率还包含重复测量，实际只有12个独立问题。意图、路由、工具正确率和人工漏转用于检查增加上下文是否干扰决策，不当成客服总体准确率。

长度分别记录：Qwen三个前向各自实际token数，Jev返回的`usage.input_tokens`。两种tokenizer和请求封装不同，不能用同一个数字假装两边计算量相同。

增长分析先对每个问题取三次重复的中位数，再算最长档减最短档，最后在12个问题间平均。再比较“Qwen增长−Jev增长”，按问题做4000次bootstrap得到探索性95%区间。它比直接把288条相关请求当成独立样本更合适，但不能排除网络、远端缓存或热状态造成的系统误差。

## 边界

本次只有一种“无关且已结束的阅读记录”干扰方式，标签继承自未经人工复核的合成样本。增加上下文同时增加了内容，不能认为数学上只改变长度；真实多轮纠正、矛盾记录和截图还未在本实验验证。

重复输入可能触发远端缓存，Jev的缓存和动态负载不可见；也没有逐项隔离GPU功耗和时钟。因此结论必须限定为本次输入、设备和API会话的调用方案，不推导Jev内部架构，更不能保证所有长输入都保持同样趋势。
