## 数据完成了什么

184条训练线索全部按完整消息、历史、认证状态、可用工具及能力设定阅读，由独立子agent起草，主agent复核。

|处理|条数|含义|
|---|---:|---|
|保留|149|在新规则下仍认可原动作；理由与政策版本另行记录|
|修订|11|9条纯人工联系方式查询改为retrieve，2条具体代发/预约请求改为human|
|隔离|24|无法唯一分清一般咨询渠道与实际人工接手，暂不提供新标签|
|可保留的标签候选|160|149＋11；这是修订包，不是完整训练集|

160条候选分布：human 100、retrieve 37、answer 14、close 8、tool 1。它们刻意聚焦本轮人工边界，不能单独当成均衡八动作训练集。全部保留AI合成/AI审核来源，没有标成人工制作或人工复核。

具体修订包括：

- “能给我人工咨询电话或渠道吗？”在一般介绍背景下是公开信息查询，有知识集合时选retrieve。
- “替我预约一次优享贷人工咨询，预约成功后给我编号。”是具体操作请求，当前工具不支持，选human；不表示已经预约成功。
- “你能替我把这段贷款咨询发给人工客服吗？”结合已写好的问题，是礼貌形式的具体代发请求。本次独立复核认可human；与“你支持自动发送吗？只问能力”区分。
- 普通致谢保留answer，明确结束保留close，不因为出现“人工”就全部改human。

24条隔离记录涉及23个来源场景组，在原训练池中共关联80条记录。`quarantine-groups.json`列出关联记录，下一版完整发布必须整组解决或隔离，不能只删当前24条就认定无污染。160候选中若有同组记录，也不能绕过这项要求直接训练。

**尚未完成全量输入迁移。** 此修订包保留原input，只变更标签建议。旧`handoff_connected`仍未强行映射到新`handoff_available`或实际会话状态；知识库档案也没有批量伪装成当前已接通。新协议输入、整个训练池的政策适配和新评估仍待下一阶段完成。因此所有输出均`training_eligible=false`，候选为`train_candidate`，不会被原训练流程自动使用。

## 八动作怎样接入后端

新增`support-financial-v2`，与原`support-classifier-v1`并存。两仓库持有同字节的`support-financial-v2.json`，请求与响应均校验政策文件SHA256；配置错误不能静默套用旧V5权重。

1. Node从已鉴权用户、后端会话和工具白名单构造输入，客户端提交的身份/能力字段不能覆盖它。当前能力明确为无知识库、无人工连接。
2. 请求`task=action`，候选为八动作；只有选到tool且认证/可用工具满足时，再请求`task=tool`五选一。
3. 编号、状态码由后端从可信会话及显式用户请求中提取和校验，模型不生成账户身份或任意工具参数。数据库读取继续以当前用户归属约束。
4. `retrieve`没有连接器时保留模型选择的审计信息，最终返回answer并说明未执行检索；human不伪报已建单，redirect提供服务范围指引。
5. 响应`decisionTrace`区分模型动作/工具、实际动作、参数修正、能力降级、规则回退和fixture；数据库审计保留更完整过程。

新版未沿用旧的关键词语义前置guard，避免“引用、否定违规词”在模型运行前就被全部误拒绝；但鉴权、白名单、参数来源、账户归属和只读工具限制仍在。没有写入型贷款工具。这不代表语义安全已经通过真实模型测试；新的模型仍须接受拒绝/误拒绝等验收。

普通clarify只追问具体问题/页面提示，不再一律要求申请编号；只有明确单笔查询缺编号才追问编号。新版会话处理占用期限也按两次模型请求、工具和回复的最大耗时留出余量，避免长请求尚未完成就被判定过期。原V5路径和默认配置未切换，App页面不需要修改。

## 本地验证和启动

在qwen项目根目录，无数据库、无GPU、无外部API即可复验：

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.financial_contract_revision validate
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_financial_contract_revision.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_financial_serve_v2.py
.\.venv\Scripts\python.exe scripts/verify-financial-v2-http.py
```

最后一个命令自动启动回环地址临时端口的Flask，运行相邻仓库Node验证脚本后关闭服务。仓库布局不同时用`--backend-root <后端目录>`指定位置；文档和代码没有硬编码本机绝对路径。需要现有Flask/werkzeug依赖及Node；如环境缺少服务依赖，在已有环境安装`requirements-serve.txt`，不要为此重复安装Torch。

在业务项目的`后端/`目录：

```powershell
npm run test:support:financial
npm run test:support:providers
```

后续具备真实数据库配置、服务配置并准备实际验收时，可以显式选择新协议：

```powershell
# 新八动作Jev：从现有本机私密环境读取JEV_API_KEY或JEV_API_KEY_FILE。
# 发出客服消息会调用API，本轮只测试了适配器，未执行该付费验收。
$env:SUPPORT_DECISION_FALLBACK = 'error'
npm run dev:support:financial:jev

# 新八动作本地模型：先有匹配新政策的真实模型服务，再设置其URL/KEY。
# 本轮没有合格新权重服务，不要把旧V5端口当成新协议。
npm run dev:support:financial:qwen

# 原V5命令仍然保留。
npm run dev:support:jev
```

显式financial启动命令负责选择协议；若手动长期设置过`SUPPORT_DECISION_PROTOCOL`，恢复旧链前需清除该环境变量或改回`support-classifier-v1`。本轮未改实际`.env.local`、默认provider或服务进程。

Flask模块`financial_serve_v2.py`提供严格校验的`create_app(engine, token)`接口，未来合格engine需明确绑定protocolVersion/policyHash并提供`predict(input, task)`。**当前CLI仅支持显式固定响应夹具，未加载Qwen权重，不是可聊天模型服务：**

```powershell
# 仅手动调试协议，临时密钥两端一致；不要用于模型效果测试。
$env:QWEN_DECISION_KEY = [Guid]::NewGuid().ToString('N')
.\.venv\Scripts\python.exe -m qwenlab.financial_serve_v2 --fixture-action tool --fixture-tool queryMyCreditScore --port 18766
```

该服务每次固定返回同一动作，响应强制`fixture=true`；Node默认拒绝它，只有明确的本地测试设置`SUPPORT_FINANCIAL_ALLOW_FIXTURE=1`才接受。推荐优先使用自动HTTP验证脚本，它生成临时密钥且自动关闭服务，不需要手动更改正常配置。

## 验证范围与下一步

真实HTTP联调10次请求：八个动作各一次、tool的第二步一次、默认拒绝fixture一次；验证了账户归属参数与无KB降级。测试使用假数据库对象和固定模型输出。它证明协议、条件调用及后端执行路径接通，**不证明模型会选对动作，也不是实际数据库端到端验收**。

独立子agent发现并复验了Flask两项修复：非ASCII鉴权头不再导致500，带首尾空白的超长原始消息也会被拒绝。CPU服务测试5项、数据修订校验测试4项通过。后端新增测试、旧provider回归和跨进程证据见相邻业务仓库更新文档及[HTTP证据](evidence/financial-v2-http-smoke.json)、[独立审查](evidence/financial-serve-v2-review.json)。

后端新增11项、旧provider 11项、旧客服14项，共36项均已验证通过。其中旧跨进程重启测试初次因沙箱禁止spawn而失败，在受审授权下单独重跑通过；其余35项原运行通过，未修改旧测试降低要求。这些SQL相关旧测试只使用隔离SQLite，不代表MySQL验收。
