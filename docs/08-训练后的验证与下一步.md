# 训练后的验证与下一步

目标是验证本地模型能否在中文客服意图、路由、工具选择上接近 Jev，同时具有可接受的延迟和成本。完成一次训练不等于达到这个目标。

**执行更新：本轮完整效果、校准、迁移和速度实验均已完成。** 实测结论见 [效果与速度验证总表](09-效果与速度验证.md)：公共意图和业务路由改善，但 CrossWOZ 迁移仍有明显差距；候选输出层的 P50/P95 仅改善 1.30%/2.27%，不采用为默认实现。下面保留当时预先制定的顺序和门槛；扩数据再训练、Mugi、图文验证仍未执行。

## 接下来的顺序

### 1. 收齐本轮证据，再判断是否接近 Jev

完成新业务挑战 180 条、公共中文意图 2,974 条、旧业务回归 72 条和 CrossWOZ 200 条的基础模型／所选模型／Jev 对照。保留 API 失败、全部错例、分组置信区间以及单请求 P50/P95，不能只挑改善最大的指标。

重点看意图准确率、路由宏 F1、真正需要工具时的联合正确率、人工漏转与误转，以及全部字段同时正确率。含大量 `none` 的工具准确率不能替代工具链路指标。新脚本 `post_training.py` 补充按业务状态和语义家族的切片，以及同一表达在不同状态下是否都选择正确路由。

先把“略弱于 Jev”具体化为探索目标：主要准确率差距不超过 3 个百分点，工具必要子集不出现明显退化，人工漏转不高于 Jev，同时延迟有稳定优势。这是后续方案筛选目标，**不是已达到的结果或生产 SLA**。小样本区间过宽时结论为证据不足，不能据此宣布等效。

### 2. 在不重新训练的前提下测首 token 加速

当前分类仍计算最后位置对整个词表的 logits，再取 A/B/C 等候选。独立实验先取输出层中对应候选的权重行，再做投影：

```text
原实现：输入 → 完整模型隐状态 h → 全词表 W h → 取候选分数 → softmax
试验项：输入 → 完整模型隐状态 h → 候选行 W候选 h → softmax
```

这仍是首 token 分类，不是新分类头，也不是 Mugi 架构。输入理解的主干计算完全保留。有限精度运算可能因矩阵形状变化而产生差异，因此不能只凭代数等价就替换实现。

实验使用同一所选模型、同一精度、同一设备、同一提示，完整对比业务开发集与公共开发集共 543 个任务预测。记录类别变化、最大 logits/概率差异；另外固定抽取 12 条开发业务请求，重复 3 次、交替实现顺序，记录包含分词与结果回传的三任务串行请求延迟。加载和预热排除。

预设门槛：候选类别全部一致，最大概率差不超过 0.01；P50 和 P95 都下降至少 5%，才值得继续独立验证。未通过也保留结果。不会据此改写第四轮的测试成绩或自动替换默认推理实现。显存实验保留原输出层，不能把这项测试宣称为部署显存优化。

### 3. 复核数据，再决定扩数据还是延长训练

优先复核开发错例及其状态对照，区分标签歧义、路由错误、选错工具、状态理解不足与泛化失败。人工复核还未完成，生成待审清单不等于完成标注。

下一批数据应增加真实或独立编写的有效场景：口语和错别字、多轮指代、长历史中的状态更新、多意图冲突、缺少申请编号、工具超时或返回空值、工具返回与页面状态冲突、用户要求越权、业务范围外问题。不同表达包装和模板复制不算独立业务覆盖。

先冻结下一轮的独立验收集，再扩训练集。已用于诊断的旧测试集保留作回归，不能继续称为完全未见。按对话／场景组划分，检查近重复，记录来源、标注理由和复核状态。Jev 输出继续只用于比较，不作为训练标签。

训练对照建议先做两种，依次运行：

1. 固定数据与提示，对比 1 轮、2 轮的开发学习曲线；检查点与选择规则提前固定。下一轮训练入口须先支持优化器、调度器和随机状态恢复，不能把只保存 LoRA 权重称为无损续训。
2. 固定训练规则，对比当前有效数据与新增场景数据；记录任务曝光次数和总更新数，避免把更多算力的收益都归因于数据量。8k 是可选阶段目标，不是立即复制到 8k 的指令；20k 在前一阶段有效后再考虑。

当前 8GB 设备已经实际完成 2B QLoRA 的这一轮训练，支持继续中等规模实验。更大数据通常增加时间而非每一步显存；更长输入、图像、更大模型和更大 batch 则可能增加显存。不能据本次成绩承诺大模型全参数训练。优先串行比较、开发早停，再决定是否需要云端算力。

### 4. 校准与兜底在独立数据上验证

温度缩放只调整置信度，不改变候选排名，不能提高原始类别准确率。先检查校准前后 NLL、Brier、ECE，再在开发／校准数据上选择自动处理门槛；测试集仅用于一次确认。

业务决策链路建议保留明确输出：路由、候选工具、校准分数、拒绝自动处理的理由，以及交给人工／回复模型的上下文。低置信度并不一律等于转人工：缺信息可追问，普通知识可交回复模型，争议和账户安全按业务政策处理。登录、资源所有权、工具白名单仍由后端执行，不交给概率阈值代替。

门槛需要同时报告自动处理覆盖率、接受样本错误率、工具联合正确和人工漏转。不能只用总体 ECE 或“阈值 0.9”宣称可靠。

### 5. 再引入 Mugi 基线与多模态验证

Mugi 可作为第三个实际部署方案，但更换骨干、参数规模、训练数据和推理内核后，速度差不能归因于“候选打分比首 token 快”。正式比较须记录固定版本、输入契约、候选数量、相同测试样本、加载／预热／分词口径，以及批次和硬件条件。

Mugi 的技术研究与版本兼容性检查另行归档。安装时使用项目内独立环境，不升级正在复现实验的环境；先审查自定义加载代码，再下载和执行。本次先完成现有模型诊断和输出层优化，不并行占用同一 GPU 跑新模型。

文字决策稳定后，加入来自项目页面的脱敏截图集，覆盖灰色按钮、必填项未完成、贷款条件不满足、截图与后端状态冲突等场景。分别比较仅文本、图文和必要时 OCR 辅助；图片应有真实页面状态与标注，不能只测截图中文字识别。本次文本微调没有验证视觉能力，也不能认定视觉一定保持不变。

## 如何检验过拟合与客服泛化

现有成绩支持“领域决策训练有效”，但不能证明一个完整客服助手已经可用：尚未验证回答质量、工具参数、真实执行和截图。当前特别需要区分以下问题：

- **模板适应**：训练、开发和新业务挑战虽然表达组不重叠，却共享政策和生成器；可能主要学会了状态模板及固定词语。
- **训练后期退化**：第 1,582 步的开发路由和工具联合成绩略好于第 2,109 步，是停止继续训练的信号，但小样本差异不能单独证明严重过拟合。
- **迁移短板**：CrossWOZ 观测为 64%→60%，与 Jev 的 87% 差距明显；相对基础模型的差值区间跨零，不能仅据这 200 条断言已经证明灾难性遗忘或其原因。

下一轮验证按以下顺序，当前未自动开启新的训练：

1. 先让未参与模板编写的成员独立整理约 300～500 条脱敏或独立撰写的中文咨询，按实际业务覆盖多轮、省略、错别字、多意图、记录不充分、工具异常与人工争议。样本数量只是启动目标，不等于达到统计保证。
2. 在看模型预测前由两人独立标注意图/路由/工具与依据，分歧先仲裁。特别复核“已有记录是否足够回答”，不能只看 record 字段是否存在。
3. 按真实对话、用户来源或场景家族划分，不能把同一问句的不同状态和近义句拆开。保留独立验收集；已经用于分析本轮错误的集合降级为回归，不继续称为盲测。
4. 固定提示、候选和指标，同时比较基础模型、选中适配器和 Jev。报告完整字段正确、工具必要子集、人工漏转/误转、各场景表现及分组区间，不用总准确率盖住少数类别。
5. 再做同分布 train/dev 差距、多个训练种子和数据规模对照。训练损失与测试准确率不是同一量纲，不能直接比较；同一个评分器评估训练样本可补证据，但低训练误差本身不证明泛化。
6. 固定一批与标签无关的扰动测试：候选顺序、等价口语改写、无关历史、状态更新和“已有信息仍不够回答”的反例。若只对熟悉模板高分，换表达或状态结构就明显退化，才更支持模板过拟合解释。

只有独立客服样本也稳定改善、关键风险不退化，才进一步讨论灰度接入。当前不通过继续反复查看测试集来选择训练步数。
