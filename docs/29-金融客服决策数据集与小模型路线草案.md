# 金融客服决策数据集与小模型路线草案

2026-09-29。本文回应下一轮数据与模型路线咨询，是拟议方案，不表示数据集已构建、训练已启动或新模型已有本机成绩。现有冻结实验与测试集保持不变。

## 目标与范围

建立中文金融客服“下一步动作”数据，而不是金融知识问答答案合集。首版以贷款为主域，覆盖金融客服通用的身份与权限、账户查询、规则检索、信息补充、争议升级、拒绝违规操作、业务范围引导和结束会话；银行、支付、保险等领域通过独立service_scope与capability_profile扩展，不把不同机构的规则混为同一种服务政策。

相同用户话语因登录状态、记录是否充分/新鲜、截图内容、可用工具和服务范围不同，动作可以不同。模型提出下一步，后端继续执行鉴权、参数约束和归属校验。该模型不审批贷款、不承诺放款、不执行资金操作。

## 八动作草案

|动作|判定范围|须覆盖的反例|
|---|---|---|
|clarify|缺少必要对象、参数，或图片/问题不足以判断|对象明确且工具可用时不重复追问；仅已知页面并不等于已知原因|
|retrieve|需要有效版本的业务规则、条款或操作文档，且检索能力可用|不把实时个人数据问题送去知识库；未接入检索不能伪造已检索|
|tool|需要且可以调用白名单工具读取尚缺的真实业务数据|已给充分事实且只要求复述时不重复查；非法状态和缺编号不能直接执行|
|answer|寒暄、普通知识、已有足够事实的解释或如实说明能力限制|未知实时费率、审批原因不能靠常识补齐|
|human|明确人工诉求、安全事件、资金争议、需要人工权限或升级处理|普通缺信息不能都转人工；动作表示需要人工，不能等同实际已创建工单|
|redirect|合法但超出该服务范围，说明范围并引导适当渠道|不能把投诉或争议当闲聊赶走；另一个机构支持的业务不代表本平台支持|
|refuse|越权隐私、伪造材料、绕过审核、篡改审批等具体不允许的请求|合法申诉、受害者报告和普通金融知识不是违规请求|
|close|用户明确结束本次咨询|感谢、稍等、仍在查看说明不自动结束|

拒绝不等于转人工：要求伪造材料应拒绝该操作；报告材料被他人伪造应核查升级。混合请求须有版本化冲突规则、一个主动作和可选后续步骤；不能用“出现投诉/人工关键词”机械覆盖一切。尚有合理多解的样本先隔离仲裁，不强塞进单标签训练。

当前生产后端只支持六动作，retrieve/redirect尚未执行。八动作需要新契约版本、训练标签、服务输出和后端执行器一起演进；不能直接替换旧decision-v5四路由。对尚未接入的能力，数据须区分“规划中能力可用的模拟配置”和“当前能力不可用的配置”。

## 数据记录规范（拟议）

模型可见：当前话语、有限历史、可信服务端状态、当前service_scope、capability_profile、available_tools、图像。仅传服务实际能提供的状态，统一确定性序列化。

标注侧：primary_action、条件性tool_name或retrieval_collection、missing_slots、reason_code、可观察证据位置、可执行性检查、政策版本。证据可为输入文本片段、图片区域或服务端字段；不要求生成长思维链。

溯源侧：来源/原始ID/许可证/允许用途、scene_family_id、原会话ID、截图template_id、split、synthetic来源、标注与复核状态、生成/处理版本。人工复核不抹掉合成来源。图像路径相对数据根目录；标注reason和人工OCR答案不偷偷喂给模型。若测试OCR管线，必须另列真实OCR输出与原生图像路径。

八动作可以保留丰富标注，但第一阶段推理以action为主任务；只有tool动作才需要后续选工具/补参数。先比较单动作首token与联合分类头，再决定是否保留三次前向。减少前向次数有潜力降低耗时，不预先承诺加速倍数。

## 图文合成设计

优先从可控HTML/UI模板、隔离样本数据库和页面状态渲染清晰截图；金额、日期、文案和按钮状态应可追溯，不靠生成式图片随机绘制汉字。此阶段不需要修改实际App页面。截图中的数据均为虚构夹具。

每个场景保留截图、用户问题、实际可见事实和独立的后端可信状态。例如同问“这里怎么继续”：完整明确提示可answer；缺少必要页面信息或图像模糊应clarify；要确认账户最新结果应tool；要求查有效业务条款应retrieve；包含争议则按事实升级。图片不能证明当前登录身份、授权或真实资金状态。

需要覆盖：文字大小与分辨率、深浅色与不同布局、截断/遮挡、弹窗、正常与异常提示、旧截图与新状态冲突、图片中的伪指令。加入相同问题但关键图像证据不同的成对样本，以及去图/打乱图像对照，检查模型是否真正利用图像；只有图像实际影响判定的样本才用于评价视觉增益。

同一底图的裁切、压缩、主题变体和近似页面不得跨训练/测试。按原始场景族、原会话、页面模板和生成来源分组隔离，测试包含未见布局与表达。已有79、128及公共评测样本继续只测，不能直接或改写回填训练。

## 拟议规模与步骤

数值是预算建议，不是已生成数量，也不是达到该数量就保证有效。

1. 先完成动作规范、冲突处理、输入输出schema、来源许可登记及标注示例；核心标准是同一个完整输入能得到一致标注。
2. 做约2,000条文本加300条图文的独立场景试点，核对标注一致性、可执行性和视觉必要性；不是模型效果最终规模。
3. 试点通过后扩至约20,000～30,000条文本、3,000～5,000条图文。重点增加独立场景族和状态对照，不用重复模板凑数量；八动作及易混淆边界均覆盖，训练配比与预期部署流量分开记录。
4. 在扩写前按场景来源划分train/dev/calibration/test；另留未见模板、未见领域配置和稳健性挑战。盲测标签在模型固定前冻结，已看错例不得回填。
5. 用相同试点数据比较2B基线与0.8B候选，先做短文本/多轮/单截图的推理与几十步训练兼容性测试，再分配完整训练预算。
6. 用学习曲线比较2k/8k/完整规模，验证增加数据是否带来新场景收益；模型选择看dev，温度与拒答阈值只用calibration，最终test只用于冻结后的报告。

主要验收：动作macro-F1、各动作召回、该查而未查、过度转人工、人工漏判、应拒绝未拒绝、合法请求误拒绝、工具条件正确率、后端实际动作成功、图文与去图差异、工具顺序稳定性。速度分别报告文本/图文P50/P95、显存、模型调用次数与最终完成率，不能只看overall accuracy。

## 模型路线与本机边界

2B不是导致本轮退步的已证实原因。现有4060 Laptop 8GB已跑通2B文本QLoRA；小规模图文训练是否可行还要测图像token、分辨率和激活显存。新环境、权重和缓存均放D盘，不覆盖旧可复现实验环境。

|候选|定位|限制|
|---|---|---|
|现有Qwen3-VL-2B|可复用本机流程的质量基线；V5与2801冻结保留|新的八动作图文训练不能沿用旧四路由成绩直接比较|
|Qwen3.5-0.8B|官方提供带视觉编码器的小模型，适合作为优先小模型试验|不同架构，现有loader、LoRA注入、量化与裁剪代码不能假定兼容；先实测Windows/本机训练与推理|
|Qwen3.5-2B|如0.8B能力不足，可用同代较大模型进一步区分架构和规模因素|不是第一阶段必须下载的额外模型|
|Qwen3-0.6B|纯文本速度/决策基线|不能直接接收截图；OCR路线另计识字与推理总时延|
|SmolVLM2-500M|极小视觉对照备选|官方语言标注English，不作为中文金融截图主线的首选|

官方卡：[Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)、[Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B)、[Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)、[SmolVLM2-500M](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct)。这些是候选，不是本机实测结论。

小模型通常减少参数存储和计算，但实际速度取决于注意力/循环混合结构、内核、量化、图像token和前向次数；不能按2/0.8估算提速。其中文识字、否定、短历史及细粒度边界可能更弱，也可能在明确窄任务与好数据上达到可用水平。当前无证据小模型训练一定更准。首个目标是用较低成本达到业务门槛，而不是参数最小。

小规模图文起步可尝试冻结视觉编码器、限制单图分辨率/图像token、batch=1、梯度累积和checkpointing；仍须实际测峰值显存。仅训练文本并不会证明视觉决策提升；要检查视觉token未被截断、图片与标签正确对齐，并单独报告原生图文结果。
