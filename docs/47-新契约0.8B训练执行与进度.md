## 本轮目标与预算

用新版`support-financial-v2`输入与政策，从官方Qwen3.5-0.8B基座建立**全新LoRA**，验证是否学会八动作和五个只读工具。上一轮边界续训适配器与本轮探针适配器均不作为正式训练起点。

- 训练候选11,756条，每轮完整遍历一次，两轮共2,940次优化器更新。
- 200步只诊断；1,470、2,940步作为选择候选。不因诊断失败提前终止，也不自动延长预算。
- 同提示原始0.8B为本轮基线。当前服务574条训练样本的局限仍在，开发指标按三个场景分别报告。
- 开发门槛不放宽；通过后才校准，校准没有非空合格接受集则停止最终评测。符合条件才进行固定最终集评测。
- API预算0，无Jev调用；没有业务数据库访问、部署、提交或推送。

原设计文件和训练数据中的`training_enabled=false`/`training_eligible=false`保留冻结状态。新执行器只能在独立审查SHA、数据/政策SHA、模型文件SHA全部匹配时生成单独的执行协议，记录`training_enabled=true`。这是经用户授权的新执行阶段，不是改写旧冻结设计，也不会让旧执行器误读新数据。

真实GPU暂停恢复已验证：第6步暂停，检查点完整，旧进程退出后命令确认`safe_to_shutdown=true`；新进程恢复后第7步继续，已核对连续步骤与48条已处理行。证据见`docs/evidence/financial-service-v2-pause-resume.json`。这验证了本机控制流程，不等于证明所有GPU内核跨环境逐位一致。

当前Windows环境缺少`causal_conv1d`和`flash-linear-attention`优化内核，Transformers使用参考PyTorch实现；启动日志还记录了一次读取系统子进程输出的编码线程异常，训练主进程持续推进。保留原日志，本轮不安装扩展或更换包版本，以免改变冻结环境。耗时以这套实际环境测量，不能仅按0.8B参数量推断一定更快。

时间估算包含的范围必须区分：进度命令的`remaining_train_minutes_estimate`只估算剩余优化器更新，不包括后续评估、校准、保存、加载及系统负载变化。全程多久以本机探针与实际进度为准。

## 常用命令

在qwen项目根目录运行。缓存、检查点、日志和结果均在项目所在盘，不新装环境。

```powershell
# 查看当前正式训练进度
. .\scripts\use-env.ps1
.\.venv-qwen35\Scripts\python.exe -m qwenlab.financial_service_v2_cycle progress

# 持续查看，每20秒更新；Ctrl+C仅退出观察，不停止后台训练
.\.venv-qwen35\Scripts\python.exe -m qwenlab.financial_service_v2_cycle progress --watch

# 安全暂停：必须等命令明确输出“可以正常关机”后再关机
.\scripts\pause-financial-service-v2.ps1

# 次日恢复同一次实验
.\scripts\resume-financial-service-v2.ps1
```

首次启动命令为`.\scripts\start-financial-service-v2.ps1`。已有运行不能重复启动，暂停或中断后用resume；已完成的运行不会重跑。不要用旧的`start-qwen35.ps1`启动本版。

只有明确需要检查本轮50步探针时，给上述脚本或Python进度命令指定名称：

```powershell
.\.venv-qwen35\Scripts\python.exe -m qwenlab.financial_service_v2_cycle progress --run-name financial-service-v2-probe
```

正式结果在`results/financial-service-v2-main/`：`status.json`当前阶段，`train.jsonl`逐步损失和耗时，`training-summary.json`行覆盖与显存，`development/<版本>/metrics.json`开发与分场景结果，`selection.json`门槛和选择；结束后自动生成`report.md`和`completion.json`。这类本地产物仍受Git忽略，不会随源码误上传；可分享的实测摘要放入`docs/evidence/`。

观察时要区分：`worker_alive=true`表示执行器进程仍在；`stage=evaluation`并不等于停止训练；`stage=complete`表示预算和收尾结束，需另外查看`passed`或`selection.json`，完成不等于门槛通过。校准和最终集未开放时，不应为“补齐表格”提前运行它们。

## 结果如何解释

报告同时保留全量准确率、八动作宏F1、逐类分母/召回、人工漏判、误拒绝、动作＋工具联合正确率，以及本机串行请求P50/P95。置信区间提供Wilson与按故事组bootstrap；有限合成数据中零错可能得到退化bootstrap区间，不能据此宣称生产无风险。

旧Jev成绩对应旧政策/输入，不能拼成新版同条件对照，也不重新调用API。只有新版同提示原始模型与本轮候选能用于本轮增益判断。请求耗时包含分词、传输到GPU和预测tool时的第二次请求，不含加载/预热/业务后端；不同阶段桌面负载不同，不作为模型规模或LoRA必然加速的因果结论。

若两轮均不达标，自动完成失败报告并停止，不追加训练，不使用开发/最终错题训练；下一步应根据分场景结果讨论数据覆盖或任务定义，而不是盲目延长时长。若通过，完成校准与最终报告后，仍需本地模型服务接入和真实后端流程验证才能讨论部署。
