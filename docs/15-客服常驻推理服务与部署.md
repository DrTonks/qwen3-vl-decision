# 客服常驻推理服务与部署

本次把已有第五轮模型接到项目客服，不新增训练，不改冻结实验数据和政策。服务只返回分类结果，真实查询由项目 Node 后端鉴权执行。云端用 Jev，不部署本地 Qwen；两者在后端使用同一输入适配与工具校验。

## 安装与启动

在 qwen 仓库目录使用已有实验环境：

```powershell
.venv\Scripts\python.exe -m pip install --cache-dir .cache/pip -r requirements-serve.txt
.venv\Scripts\python.exe -m qwenlab.serve --profile support-v1
```

本次安装 Flask 3.1.3、Waitress 3.0.2。没有重装 PyTorch 或训练依赖。profile 位于 `configs/serve-support-v1.json`，明确选择 `.local/checkpoints/joint-v5/step-7110`，不使用旧 infer.py 中的第四轮默认适配器。模型权重、虚拟环境、日志和密钥继续忽略，不上传 GitHub。

启动时加载模型、设置 eval、预热三个候选布局；输出 ready 后监听 `127.0.0.1:8011`。Ctrl+C 停止，无自动启动、后台服务或调试重载。与训练进程共用 pipeline/gpu 锁，避免显存争用。

可选 `--adapter`、`--projection full`、`--port`。默认 candidate，布局校验失败自动退回 full 并在健康状态中说明。若配置 QWEN_DECISION_KEY，调用者必须发送匹配的 Bearer；服务不记录密钥或原始问题。

## 与后端连接

后端配置 `QWEN_DECISION_URL=http://127.0.0.1:8011/decide`，从项目后端目录运行：

```powershell
npm run dev:support:qwen
```

Jev 使用 `npm run dev:support:jev`，规则使用 `npm run dev:support:rules`。这些 Node 命令属于 uestc_Integrated_Design/后端，不在本 qwen 仓库执行。云端 127.0.0.1 不能指向你的电脑；当前本地模式没有建立公网连接。

完整团队部署与检索衔接见项目仓库 `更新/客服决策模型接入与知识检索衔接.md`。

## HTTP 协议

`GET /health` 和 `/ready` 返回 ready、protocolVersion、policyHash、model、adapter、projection、projectionFallback、textOnly。服务加载完成前不监听，因此不能把“进程刚启动”视为就绪。

`POST /decide` 使用 `support-classifier-v1`，只接受 protocolVersion、policyHash、input 三个顶层字段。input 为 message、history、state、available_tools。拒绝图片、未知字段、超过四条历史、超长消息或任意工具。

state 的 authenticated、application_id、status_code、pending 由业务后端基于身份和有来源的会话内容组织。state 只是分类上下文，不能替代数据库权限校验。Jev 与 Qwen 使用同一规范化输入；不能仅把原句传给 Qwen、却不给训练协议所需的明确编号/状态码。

输出 predictions 包含 intent、route、tool 各自的 choice 和概率；保留原始工具预测，即便 route 不是 tool。是否执行工具由后端判断，不在 Python 服务内进行。Jev 一次请求返回三个任务，当前 Qwen 是三次串行首 token 前向，并没有因服务化变成一次前向。

两端按排序键的规范 JSON 计算第五轮政策哈希，拒绝不同政策。单次请求总输入上限 32 KB，编码上限仍为 2048 token，超限 422，不静默裁剪模型输入。后端最多提供四条最近消息，每条最多 800 字符。

服务只保留一个 GPU 推理实例；并发忙时 503，不无限排队。400 表示输入格式错误，409 表示协议/政策不同，401 表示令牌错误，422 表示输入超过编码限制，503 表示忙或推理失败。后端 error 模式不降级，rules 模式记录降级；无论哪种都不自动调用 Jev。

## 验证与真实结果

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_support_serve.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_candidate_inference.py -v
```

服务测试 3 项、候选投影回归 7 项通过。真实 GPU 是本机 RTX 4060 Laptop 8 GB，加载 step-7110，实际投影 candidate，没有回退。

项目端 12 条合成客服接通用例：Jev 和 Qwen 最终均 12/12。其中 3 条被共同安全/流程规则处理，各只有 9 次模型调用。九条模型路径端到端 P50：Jev 315.01 ms、Qwen 591.65 ms；P95 分别 675.27 / 797.95 ms。包括数据库和业务工具，不含 Qwen 加载。这是单轮小样本接通检查，不是新的独立准确率报告，也不能与历史冻结性能表直接拼接。

首轮 Qwen 9/12：已给申请编号、裸编号补充、状态码解释被判断为需要澄清。原因是输入适配没有把明确证据写入结构化字段，修正后通过。没有改模型权重，也没有修改正确标签来追求满分。项目验收结果目录保留适配前后证据。

本轮未训练 retrieve / redirect / refuse / close 等八动作模型。后续知识检索上线需要新政策、候选定义、人工复核测试及必要的训练，不能直接把四路由实验准确率当作八动作效果。
