# 金融客服八动作数据冻结与短试训协议

2026-10-01。本轮目标是让数据、模型任务和真实后端能力一致，并建立独立的选型流程。当前完成的是训练数据补充、独立评测、提示与200步试训协议；**尚未训练新适配器，也没有新模型准确率、耗时或Jev比较结果**。

## 为什么先补数据和验收

V1已有11,049条训练文本，但状态码解释工具只有16条，当前无知识库条件只有10条。直接训练容易把“应该检索”学成不考虑服务能力的固定动作。新增数据同时覆盖工具可用性、认证、明确对象、已有事实和能力缺口，减少仅靠句子关键词作决定的问题。

新八动作与V5合并工具的八分类并非同一个任务。这里的八动作是追问、检索、工具、回答、人工、引导、拒绝、结束；具体工具另有五分类。V5历史成绩不能作为这份数据上未经测量的基线，旧适配器也不作为本轮初始权重。

## 数据组成及用途

V2复用只读的`data/financial-training-text-v1/parts/`，新增`data/financial-eight-actions-v2/train-additions.jsonl`，不复制或修改旧训练片。显式训练适配器合计读取11,899条，评测文件不进入训练枚举。

|retrieve 检索|2500|50|2550|48|32|64|

新增850条中：800条为`current-no-kb-v1`，50条为`planned-kb-v1`；状态解释240条，另外四个工具各20条；含历史40条。总体状态解释增至256条，无知识库条件增至810条。新增稿覆盖八动作，但并非让原有各动作数量完全相同：训练协议按动作、能力条件和分组抽样，并记录实际覆盖与重复次数。

**240条状态解释只是三个固定状态码的表达覆盖，不是240种独立业务任务。** 无知识库补充也不能把原有2,550条检索样本自动变成当前无知识库条件的数据；模型必须阅读每条真实可见能力字段。

|评测分区|条数|具体子族|宏故事|无知识库|含历史|
|---|---:|---:|---:|---:|---:|
|development 开发|384|32|8|166|13|
|calibration 校准|256|32|8|115|0|
|final 最终|512|32|8|231|92|

评测作者仅依据真实业务契约起草，没有阅读训练稿或旧测试错例造题。三个分区均混合经营、居家、就业等背景，并覆盖全部五个工具。最终集包含较多自然短问句，必要事实放在可见历史或可信状态中；开发/校准仍包含较显式的能力条件题。**校准集没有历史题，三个分区难度不完全相同**；校准收益必须在最终集独立核验。

这些新稿均为AI合成，独立agent逐条实际阅读输入与标注，`human_review=false`。不是人工金标，也不是真实用户流量。V1的来源筛选和局限见[上一轮报告](35-金融客服训练集筛选与少数动作补充.md)。新评测作者虽与训练作者隔离，仍可能共享生成模型的写作习惯。

## 与后端契约对应

以项目实际Node客服工具实现为依据：五个工具均需认证；单笔申请要求已明确完整编号；参数和数据归属继续由后端校验。

|工具|可使用的能力|不能据此声称|
|---|---|---|
|queryLoanProducts|已发布产品的编号、名称、金额上限、参考分、标签；最多返回50条|已查询具体利率、完整所有产品或个人资格结论|
|queryMyApplications|本人接口可返回范围内的申请列表及状态|已取得无限范围的全部申请历史|
|queryApplicationDetail|明确编号的本人单笔申请明细|能够查看其他人的申请或替用户修改结果|
|queryMyCreditScore|本人已有评分、档位、建议额度|新的征信查询、授信承诺|
|explainApplicationStatus|解释0/1/2状态码，不查询本人实时进度|已经查询了个人申请或拒贷具体原因|

实际状态映射为0未通过、1已通过、2待审批。提示只说明工具支持0/1/2，**不把码义映射作为已知事实塞进提示再要求调用工具**。

`retrieve`针对正式知识集合可用时的未知平台规则；`current-no-kb-v1`时不能选择不可用检索。`answer`允许根据已给信息解释或如实说明限制，不意味着模型自己猜贷款政策。`human`选择也不代表已经接通人工；争议受理状态由后端确认。合法域外需求归引导，明确造假、越权才拒绝。

## 独立性、复核和冻结证据

正式目录的`manifest.json`绑定父训练版本、新训练片、三个评测数组、场景目录、协议及原始独立审查包。审查包不仅绑定文件SHA256和完整ID，还逐条绑定输入、标注、来源、场景族和评测分区，防止替换题目后只重签分片冒充旧审查。

组隔离同时考虑来源对话、场景族、遮蔽编号后的文字/历史，以及评测宏故事。一个宏故事的四个子族必须留在同一分区。96个子族实际只有24个宏故事，每个分区8个；**不能把1,152条当作1,152个独立用户**。后续区间按宏故事聚类计算，8个聚类仍然偏少，应与逐类召回和实际错例共同解释。

另对新评测与旧候选/新训练/其他评测做遮蔽后的有限词法近似筛查。当前消息三元字串检索、有限候选和相似度阈值只是筛查，**没有完成全量语义去重**。发现相似对时独立读取两侧可见上下文，不能因标签都正确就自动放行同模板跨分区。冻结前修正保留旧稿与差异记录，不使用模型测试错误改写训练稿。

三个评测文件采用普通JSON数组，显式由V2保护；旧实验的JSONL保护索引和源码保持原样。便携校验检查发布包内部证据一致性，本机`--verify-local`额外重建原始来源和源码绑定。它们不是外部数字签名，无法证明有人协调篡改整套证据后的真实性。

## 如何复查和使用

先读正式版本：

- 新训练：`data/financial-eight-actions-v2/train-additions.jsonl`。
- 开发：`data/financial-eight-actions-v2/evaluation/development.json`。
- 校准：`data/financial-eight-actions-v2/evaluation/calibration.json`。
- 最终：`data/financial-eight-actions-v2/evaluation/final.json`。
- 分组：`groups.json`及`evaluation/catalog.json`；审核证据：`reviews/`；冻结协议：`protocol.json`。

每条检查`input.message/history/state/capabilities`是否足以支持`annotation.action/tool_name/tool_arguments`。先读可见输入再看标注，尤其检查认证缺失、未知规则、人工争议、结束与取消申请的边界。`annotation.reason`用于审查，不能进入模型提示；来源和场景ID同样不能进入输入。

可编辑工作副本及按动作阅读稿在`.local/financial-eight-actions-v2/human-review/`。只改副本或另写ID对应意见，正式冻结文件保持原样。用户修改并不自动获得通过状态，需要重新独立复核和发布新版本；如果模型已经看过最终集，再改这些题也不能称为从未使用的盲测。

在仓库根目录执行PowerShell：

```powershell
# 发布包校验：克隆仓库后无需本机.local原稿
& .\.venv\Scripts\python.exe -m qwenlab.financial_ready validate

# 本机来源重建和源码绑定校验，需要作者/审核原稿仍在.local
& .\.venv\Scripts\python.exe -m qwenlab.financial_ready validate --verify-local

# 显式导出父训练片+新增训练，不包含评测；保存在.local
& .\.venv\Scripts\python.exe -m qwenlab.financial_ready export-training

# 数据、隔离、指标与门槛代码测试
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_financial*.py'
```

发布器的`audit/build`用于冻结前准备；`build`拒绝覆盖已存在版本，不应通过删除正式目录来重跑。本轮没有提交或推送Git，`.local`、模型权重和密钥保持忽略。新增数据目录通过`.gitattributes -text`保留哈希绑定字节，避免Windows换行转换。

## 短试训协议和下一步

协议源为`configs/financial-eight-actions-pilot-v2.json`，发布副本为`protocol.json`。本轮仍使用已经下载的Qwen3-VL-2B-Instruct；没有下载更小模型或比较其效果。换模型需要另立基线与预算，不能仅凭参数量推断更快或更准。

1. 先实现并审查新任务训练/推理执行器，用本地2B原始模型跑**同一提示**开发基线，记录真实prompt、协议、数据和模型hash、概率、输入token、延迟及失败。
2. 新建QLoRA适配器，不续接旧V5/V8。NF4、BF16、SDPA；仅语言q_proj/v_proj，视觉冻结；r=8、alpha=16、dropout=0.05。最多200优化步，微批2、累计4，学习率5e-5、预热20、权重衰减0.01，第100/200步保存检查点。按实际覆盖日志判断是否需要后续扩大预算，200步不等于遍历全数据。
3. 动作任务训练八个候选；仅真实tool训练行再训练五工具任务，工具损失权重0.75。推理时仅**预测tool**才执行第二次工具决策，不能用真实标签替模型决定是否运行。两任务共享权重但使用两次提示/预填充，不宣称一次推理完成动作与工具。参数提取及归属校验单独报告。
4. 仅开发集选择候选并检查下面门槛；失败则诊断、记录和结束该预算，不自动长训或放宽门槛。
5. 合格后固定候选，校准集仅调温度和兜底阈值。冻结校准方案后，最终集对固定候选与同提示基础模型做一次对照；最终集不选模型、不回填训练。需要继续改进时准备新版本和新的独立最终测试。

|开发门槛|要求|
|---|---|
|八动作宏F1收益|比同提示原始模型至少+0.01|
|各动作召回|均≥0.80|
|人工召回|≥0.95，且相对基线不新增漏判|
|非拒绝样本误拒绝|相对基线不新增|
|知识集合不可用时预测检索|0条|
|真实tool上的动作+工具联合正确率|≥0.90，动作选错也算失败|
|状态解释工具联合正确率|≥0.90|

这些门槛由代码拒绝最终/校准选型、不同输入/提示/协议混比、NaN与缺失动作支撑。门槛函数仍依赖执行器诚实记录实际运行绑定，不能仅传任意hash字符串就宣称运行可复现。

速度分别记录动作一次、动作加条件工具二次、后端参数与保护的P50/P95及输入token分布，预热10次；训练分钟数要等本机真实吞吐测量后估算。现阶段只有数据协议和指标实现，**没有可用的新试训启动/进度命令，不能把导出命令当训练命令**。下一步交付执行器、开发基线和200步实测结果，再决定长训、小模型、Jev预算或多模态。图文数据和多模态训练不在这份文本版本内。

## 代码阅读入口

- `financial_ready.py`：显式训练/评测读取、组隔离、来源复核、冻结发布与校验。
- `financial_actions_prompt.py`：仅可见输入的动作和工具提示，单token候选校验，超长输入拒绝静默截断。
- `financial_actions_metrics.py`：混淆矩阵、宏F1、人工漏判、误拒绝、不可用检索、联合工具和参数来源口径、开发门槛。
- `tests/test_financial_ready.py`：分区误用、提示泄漏、审核绑定与篡改、oracle工具、分母、NaN和选择门槛等针对性测试。

这套数据用于检验模型能否决定下一步，而不是训练生成整段客服回答。决策之后的知识检索、真实工具结果、回答模型、人工受理与业务保护仍需分别完成并验收。
