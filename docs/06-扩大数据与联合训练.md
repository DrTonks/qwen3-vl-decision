# 第四轮：扩大数据与中文决策联合训练

## 目标与验收口径

目标是让意图、路由、工具和人工转接尽量接近 Jev，并保留本地运行的延迟优势。一般准确率差距不超过 3 个百分点可作为后续候选门槛；本轮只有 180 条合成业务挑战，尚不能据此认证微小差距或产品可靠性。

这不是“再把 48 条多训几遍”。本轮使用去重完整 MASSIVE 中文训练数据和新的状态对照课程。也不是已经具备数万条真实业务数据：必须把文本条数、表达组、语义场景和人工复核状态分开记录。

## 数据

|集合|业务条数|表达组|语义家族|用途|
|---|---:|---:|---:|---|
|训练|2,048|128|20|训练意图、路由、工具，每条产生三个分类问题|
|开发|90|26|20|选择检查点，不调整测试标签|
|校准|90|26|20|拟合温度，不参与参数训练|
|挑战|180|52|20|冻结后比较本地与 Jev|

业务数据由同一个作者按同一政策构建，**全部为 synthetic_unreviewed**。训练每组含四种表达/多轮形式及状态对照；其所有变体固定在同一 split。不同集合没有完整输入或表达组交叉，但共享政策、语义家族和生成代码。因此这是表达留出与状态组合测试，不是未见业务政策或真实用户的独立盲测。不能把 2,048 条等价成 2,048 个独立场景。

状态覆盖：已登录/未登录/登录状态缺失、记录已提供/待查询、工具可用/缺失、本人/他人记录、申请编号缺失、状态码 0/1/2、界面已提供禁用原因/缺少上下文/普通排查失败，另有还款咨询、扣款争议、身份盗用、诈骗、人工诉求、修改审批等语义家族。

MASSIVE 官方中文 train 原有 11,514 条，剔除与官方 dev/test 的归一化重复和训练内部重复后为 **10,725 条**。这次完整遍历，不再每类只取 30 条。公共开发 273、校准 313、测试 2,974 条沿用冻结 v2 数据；测试为旧公开基准回归。CrossWOZ 200 条仅作迁移压力测试，未加入训练。旧业务 72 条也单列回归，不能与新挑战混合计算总准确率。

生成代码：`src/qwenlab/joint_data.py`。清单和 SHA256：`data/processed/v4/manifest.json`，执行时复制进公开实验协议。成员标签复核表位于本地 `.local/review/joint-v4/development-review.csv`；无人复核前不得更改 label_status。

## 训练与选择

基础模型、量化和适配目标沿用既有方案：Qwen3-VL-2B-Instruct、NF4、语言 q_proj/v_proj、LoRA r=8/alpha=16/dropout=0.05；视觉冻结。学习率 1e-4，5% warmup，AdamW，梯度裁剪 1。实际训练参数 1,605,632。

完整遍历一轮：10,725 个公共意图问题 + 2,048 × 3 个业务问题，共 **16,869 次分类样本**。micro batch=4，梯度累积=2，最后不足批次仍保留，合计 2,109 次优化器更新。每个任务的样本都被遍历一次；没有通过有放回抽样隐瞒覆盖率。

损失权重为：公共意图 0.5、业务意图 1、业务路由 2、业务工具 1.5。这里同时扩大了数据并调整任务权重，因此最终差异是整套联合训练方案的效果，不能拆称某一种数据或某一个权重的独立因果贡献。

在约 25%/50%/75%/100% 进度保存四个适配器，在新进程中按部署精度重新加载后评估开发集。选择目标为公共意图准确率、业务意图准确率、路由宏 F1、真正需要工具时联合正确率的几何平均；每项不得低于基线 3 个百分点，人工漏转数不得多于基线。基础模型参与选择；如果所有适配器都不满足约束，保留基础模型。挑战预测不参与选择。

这是一轮完整样本遍历、单种子实验，不是多种数据规模的学习曲线。四个检查点展示训练进度变化；2k/8k/20k 的数据规模曲线需要后续新增有效场景和独立运行，不能把本轮检查点伪装成数据规模对照。

## 数值与工程预检

初次预检使用“批处理与单条绝对 logit 差不超过 0.5”的门槛，未通过。保留诊断后发现 NF4/BF16 在不同批量形状下存在数值差异；扩大到 16 条不同任务输入，候选选择全部一致，但最大概率差约 0.109。不能据这 16 条宣称所有输入都等价。

因此训练仍使用批处理，**所有正式评分、校准和单请求计时固定单样本逐任务推理**，不利用批处理速度美化部署延迟。反向预检选择较长输入，batch=4 的峰值 allocated 为约 4.65 GiB，有限损失与梯度检查通过。

首个预检失败的代码协议与记录保存在 `.local/archive/joint-v4-initial-preflight`；改动发生在正式训练开始前。正式协议的代码、配置和数据哈希保存在 `results/joint-v4/protocol.json`。

## Jev 与校准

Jev 只作采购/选型评估，输出绝不进入训练。新业务挑战最多 200 次、实际计划 180 次请求，无隐藏重试。服务模型列表只暴露 `jev-latest/jev-preview`，不支持按 `jev-1.13.0` 名称选择；请求使用 latest 别名，但逐条检查响应必须仍为 1.13.0，否则停止并禁止混用历史结果。

公共、旧业务和 CrossWOZ 可以复用已记录的 1.13.0 结果，因为输入、政策和候选不变。复用来源及 SHA256 单独记录，不能宣称重新调用了 API。API 失败不删去；同时记录失败数与将失败计错的准确率。

意图和路由分别在校准集拟合正温度，随后应用到挑战。人工标记由路由推导；非 tool 路由强制工具为 none，这两者属于工作流约束，不计作两个独立模型能力。工具参数、真实工具执行和图片未验证。

## 运行命令

先完成 README 的环境、模型、原始数据及 v2 数据准备。从项目根目录执行：

```powershell
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.joint_data
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "*.py" -v
.\.venv\Scripts\python.exe -m qwenlab.joint_v4 run *> .local/joint-v4-console-v2.txt
# 上一步失败时先排查日志，不继续以下命令
.\.venv\Scripts\python.exe -m qwenlab.joint_jev
.\.venv\Scripts\python.exe -m qwenlab.joint_complete *> .local/joint-v4-completion-console.txt
# 完成器执行迁移、校准、结果文档和审核；加速实验必须等其完成
.\.venv\Scripts\python.exe -m qwenlab.candidate_benchmark --wait
.\.venv\Scripts\python.exe -m qwenlab.integrated_report
.\.venv\Scripts\python.exe -m qwenlab.publish --export
```

GPU 训练和 GPU 评估串行；Jev 不使用 GPU，可以独立执行。运行名和冻结数据不覆盖，复现实验应放在新副本中。所有环境和大文件保留在项目所在盘；个人学习文档、密钥和权重不进入发布包。
