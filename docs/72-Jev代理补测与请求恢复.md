# 当前开发集五模型对比与 Jev 代理补测

2026-10-16。128 条评测完成，离线复核通过。评测阶段没有训练、读取校准/最终集或切换部署；后续按用户授权整理百分比表格并发布，见[多维对比](73-五模型多维性能对比.md)。

## 结果与建议

同一份开发数据与业务政策；预测为 tool 时才串行调用工具选择，不使用真实标签决定调用路径，不加入后端规则补救。训练后选择各自完整训练中动作准确率最高的检查点（两者均为 step 1673），其他指标来自同一检查点。

|---|---:|---:|---:|---:|---:|
| Jev 1.13.0 | 85.16% | 76.88% | 72.22% | 88.89% | 0.00% |
| 原始 Qwen3-VL-2B | 30.47% | 30.84% | 27.78% | 33.33% | 0.00% |

| 训练后 Qwen3.5-0.8B | 94.53% | 95.58% | 100.00% | 88.89% | 1.82% |

0.8B 在本集比 Jev 多答对 12 条（+9.38 个百分点），2B 多答对 8 条（+6.25 个百分点）。但三个方案都漏转人工 3 条，训练后小模型还存在误拒绝，不能只凭总体准确率替换默认服务。继续保留 Jev 默认，0.8B 作为业务加权实验基线；本次不宣布任一候选通过上线门槛。

Qwen 使用任务微调、Jev 根据给定政策零样本决策；开发集参与检查点选择。这是当前任务上的适配比较，不是通用能力排名。128 条来自 32 个合成场景组，并非 128 个独立真实用户。Jev 按场景组 bootstrap 的动作准确率区间约 78.13%—91.41%，也不代表真实用户分布上的保证。

当前服务子集为 53/64（82.81%），规划检索子集为 30/32（93.75%），登录前健壮性子集为 26/32（81.25%）。检索高分只说明能选择检索动作，不意味着知识库已经接通或回答正确。引导样本只有 4 条，不能据此断言该能力普遍为零。

漏转人工样本：`EVAL-FSV2-DEV-0030`、`0083`、`0094`；另有 2 条未认证状态下选择工具（`0100`、`0125`）。服务端仍需鉴权、能力检查及执行约束。本表是决策组件结果，不是经过后端保护的端到端指标。评测错题仅用于分析，不回流训练。

## 响应异常与计时口径

供应商返回的一条动作结果（`EVAL-FSV2-DEV-0002`）为 `choice=answer`，但概率为 `tool=0.49`、`answer=0.48`。这与[官方 choice 响应说明](https://docs.typesafe.ai/primitives/choice)中选择概率最大项的定义不一致。原始响应已保留，未修改答案、未重发挑答案。

主要指标按实际 `choice` 计算；额外把任一任务出现该异常的整条样本计失败，严格动作得分仍是 109/128、工具联合得分仍是 13/18，因为该条原本就答错。全套 146 个成功请求仅发现这 1 条 choice/概率异常。它不影响本次总分，但正式接入需要明确处理策略；本次未修改线上 provider。

Jev 是 HTTP 调用耗时之和：每条动作请求，加上预测为 tool 时的工具请求。包含网络、代理及服务处理，Qwen 是本地历史测量（含分词、按需工具选择，排除加载）。两边均排除后端业务执行和回答生成，未同期交错测量，不能推导纯模型计算加速倍数。原始 0.8B 较慢还与更多样本误选 tool、触发第二次计算有关，不能据此断言微调使单次前向更快。

- 成功 HTTP 耗时：P50 **323.59 ms**，P95 **1,381.23 ms**。
- 计入三个代理阶段所有失败尝试和已记录退避等待：P50 **323.59 ms**，P95 **1,413.71 ms**。
- 不计等待人工授权、诊断、进程启动或无密钥 GET 探测。最初一条完整样本复用 urllib 成功记录，其余使用连接池；这是一轮含恢复的测量，不是假定无故障的干净压测。

## 执行过程与请求账本

此前直连 HTTP451 记录留在[报告71](71-Jev当前开发集补测与访问阻断.md)。用户指定本机 7890 代理，并在首个工具请求失败后明确允许多次重试和测试。本次全程验证 TLS、禁止重定向、无直连回退，密钥仅从本地忽略目录读取。

1. `financial-jev-current-proxy-v1`：urllib 传输取得 2 个成功响应、6 次结果不确定的连接失败；达到单请求重试上限后停止。无密钥检查显示连接被重置。
2. `financial-jev-current-session-v1`：无密钥连接池检查 4 次正常后，更换为 requests.Session，复用已有成功响应。增加 1 次连接失败，随后取得上述 choice/概率不一致的响应，原严格检查器停止。
3. `financial-jev-current-session-v2`：在独立协议中明确“保留供应商 choice、额外报告异常失败口径”，复用 3 个成功响应完成评测，没有新增失败。旧协议与源码保留，不覆盖冻结实验。

最终共 **146 个唯一成功请求（128 动作 + 18 工具）、7 次失败或结果不确定尝试，153 次模型请求尝试**；成功响应报告 **169,240 输入 token、11,096 输出 token**。失败请求的用量与费用未知，不能算零费用。实际费用应以供应商账单为准；没有为了更高成绩重测已返回答案。

注意：核心执行器的 `completion.json` 中 `retries=0` 指其内部无重试，单阶段 `retry-accounting.json` 也不含此前阶段失败。跨阶段总账以 `comparison-audit.json` 的 `all_proxy_phases` 为准；缓存复制不重复计请求。
