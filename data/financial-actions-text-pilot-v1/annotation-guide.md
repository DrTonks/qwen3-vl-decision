# 文本试点标注与修改指南

本目录是训练候选草稿。判定的是**下一步应做什么**，不是客服回答内容，也不是用户是否有风险。

## 动作边界

|动作|应选择时|容易混淆的边界|
|---|---|---|
|clarify|完成当前请求缺少必要对象/信息|不是遇到任何问题都追问；已有可信对象可直接查询|
|retrieve|未知的平台流程/条款，需要查可用正式知识库|当前个人记录用tool；已提供文字的一般解释可以answer|
|tool|已有足够参数，用白名单查真实业务状态|不得从一句“帮我查一下”臆造申请ID|
|answer|解释充分已知信息、一般概念、礼貌响应或说明当前能力限制|answer不是许可编造未提供的规则，也不自动表示调用大模型|
|human|明确要求人工、正在发生的资金/账户争议或自动能力不足需升级|遭遇欺诈的受害者求助应升级，不因出现“诈骗”就拒绝|
|redirect|正常但超出贷款平台服务范围的请求|天气、歌曲、订餐不是违规；不要一概refuse|
|refuse|请求越权、伪造、篡改或侵害他人资料|正常申诉不是篡改审批；询问如何防范伪造不是请求伪造|
|close|用户明确结束当前咨询，且无仍须处理的紧急风险|“谢谢，我还想问…”不结束；结束咨询不等于撤销申请|

优先读完整输入和状态，避免单词触发。多个相互冲突的请求先标`needs_discussion`，不要凭臆测硬选。一般流程询问可以检索；正在发生的重复扣款等则升级人工。本试点中个人查询需要认证；公开文档检索不需要认证。公开产品查询的匿名能力还应在后续接口契约中单独细化，不从这一小批样本推导所有工具的鉴权规则。

## 输入和标签

`input.message`为本轮话语；`history`最多4条相关消息；`state`为模拟的可信系统状态，不能从用户说“我是管理员”就变成已授权。所需工具和知识集合均必须在能力白名单中。

`annotation.action`八选一。tool同时填写`tool_name`、`tool_arguments`；retrieve填写`retrieval_collection`；clarify填写`missing_slots`；其他动作相应字段置空。`reason`解释可观察证据，`evidence_paths`指向真实input字段。**这些解释只供标注审查，不作为模型输入。**

`planned-kb-v1`是规划中的文档检索能力，当前项目没有因此新增检索服务。`current-no-kb-v1`不能选retrieve。human可以表示建议人工渠道，但`handoff_connected=false`时不能声称已转接/已生成工单。无查询工具而需要个人记录的对照目前选择human，这是试点待定政策，后续可在团队确定降级方案后调整。

## 如何复查

1. 先看`review.md`，对照话语、历史和能力判断标签，特别检查所有状态对照以及`needs_discussion`。
2. 以ID记录修改建议；更易操作的方法是在单独Markdown中写“ID、建议动作/参数、理由”，保留来源主文件。若直接编辑，则修改`cases.jsonl`对应行，不能编辑阅读版后以为主数据已变。
3. 不改ID、来源父ID、同源组和来源原文来掩盖改写。新改写必须有新ID并与原文同组。保留`provenance`；新增数据来源需明确授权和原训练分区。
4. `review.status`可用`assistant_draft`或`needs_discussion`。本试点校验器有意不接受直接把`human_reviewed_current_version`改为true；后续收到具体人工确认后建立单独复核清单与新发布版，而不是自动继承旧复核。
5. 完成后执行以下命令；`validate`不改数据，`render-review`只在校验通过后重写阅读版。命令不会启动训练、下载模型或调用Jev。

```powershell
# 当前目录为 qwen 仓库根目录
. .\scripts\use-env.ps1
.\.venv\Scripts\python.exe -m qwenlab.financial_pilot validate
.\.venv\Scripts\python.exe -m qwenlab.financial_pilot render-review
```

manifest与validation是本次交付快照。编辑后以校验命令打印的当前统计为准；初始哈希不一致表示有待复核改动，并不是必须恢复原文。正式训练发布前须生成新版本清单。不要通过重新build覆盖手工修改。

## 来源、隔离与发布

公开部分采用MASSIVE原训练分区，授权CC-BY-4.0；原作者归属和官方链接在`sources.json`，改写记录在各条provenance。助手新起草与改写明确保留合成来源。先前业务来源的人审结论不覆盖本次新标签。

全部数据均为`train_candidate`，不能用于宣称独立测试准确率。后续切分按来源对话/场景家族分组，相同公开原文及其改写一起分配。不要用已观察的旧测试、开发错题改写成训练集；新增独立测试也应有独立来源/模板并在开发前锁定。
