# 金融客服补充候选扩充

本目录只交付候选与审核证据，不是训练发布。全部保留 `ai_synthetic` 来源、`human_reviewed=false`、`training_eligible=false`。没有真实客户个人信息；未加载模型权重或调用收费 API。

## 阅读与编辑

- `batch-a.authoring.json`、`batch-b.authoring.json`：可编辑的作者源，各760条。按 `id` 定位消息、历史、状态、动作、工具参数、缺槽及理由。
- `build-v1/REVIEW-new.md`：1,520条新增候选的逐条可读视图，同时显示服务端状态和实际模型输入。它保留构建时“待独立复核”状态，后续审核结论另存。
- `build-v1/candidates.json`：新增1,520条与首批158条的合并快照。继承项保留原审核链；首批C08隔离组不在其中。
- `build-v1/audit.json`：完整动作/工具分词长度与结构检查，不包含模型成绩。
- `build-v1/blind-overlap.json`：历史保留集和训练池的盲词面筛查；只有本批命中ID与来源指纹，不输出旧题面、旧标签和预测。
- `reviewed-v1/accepted.json`、`reviewed-v1/quarantine.json`：最终接受和整组隔离候选；数量和原因以同目录manifest及报告51为准。
- `batch-*.notes.md`：作者阶段的统计与局限，不应视作独立审核结论。

完整统计、独立复核证据、命令与下一步见 [报告51](../../docs/51-金融客服补充候选扩充与全量复核.md)。

修改前复制作者源作新版本，修改后构建到新目录；改动组需要重新审阅语义，完整新版本则须提交逐条绑定新候选SHA的完整独立审核，不能仅提交改动组。随后全量重放与筛查。不要修改派生candidate、review或manifest来让校验通过；原快照和证据需要保留。作者脚本 `build-a.cjs`、`build-b.py` 是生成来源说明，会写作者源，**不要在人工修改后直接运行覆盖它们**。

逐条复查顺序：明确本轮真实诉求 → 核对认证/工具/知识能力 → 核对当前消息与历史里的对象和参数 → 判定动作与理由。合法但缺少处理能力不等于应当拒绝；被引用的违规请求不等于用户正在要求执行；致谢后仍有实质问题不能直接结束。

同一来源组不得拆开进入训练和评估。保留集命中只用于隔离，不能根据旧题面改词绕过筛查。词面未命中不能保证语义独立；独立AI审核也不能声称人工审核。
